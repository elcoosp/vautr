In this tutorial you run your own Vautr server, create an account, store your Emergency Recovery Kit, and save and retrieve a secret with the command-line client. You finish with a working vault that you fully control and a workflow you reuse for every future secret.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) running locally
- [Rust](https://rustup.rs) 1.85 or newer (the CLI is part of the Vautr Cargo workspace)
- A terminal

## 1. Start a Vautr server

Run the official server image with a named volume for its data:

```bash
docker run -d \
  -p 8080:8080 \
  -v vautr-data:/data \
  --name vautr-server \
  ghcr.io/vautrorg/vautr-server:latest
```

The server listens on port `8080` and stores its SQLite database under `/data` in the container. Confirm it is live:

```bash
curl http://localhost:8080/health
```

The liveness probe returns `200` while the process is serving. You can also check the readiness probe, which verifies database connectivity:

```bash
curl http://localhost:8080/health/ready
```

## 2. Build and log in with the CLI

The CLI lives in the Vautr repository. Clone it and build the client:

```bash
git clone https://github.com/elcoosp/vautr.git
cd vautr
cargo run -p vautr-cli -- --help
```

Register a new account. OPAQUE, a password-authenticated key exchange, performs the registration handshake so the server receives only a registration record — it never sees your master password:

```bash
cargo run -p vautr-cli -- register you@example.com
```

Enter your master password when prompted. Choose it carefully: it derives your encryption keys locally, and the server cannot help you recover it. Then log in to establish a session:

```bash
cargo run -p vautr-cli -- login you@example.com
```

The CLI stores its session and server URL (default `http://127.0.0.1:8080`) in `~/.config/vautr/config.json`. You can point every command at a different server with the global `--server` flag.

## 3. Save your Emergency Recovery Kit

After registration, your client provisions a 24-word BIP-39 recovery key as part of the onboarding flow. Store it in a safe place — a password manager other than Vautr, a printed card in a drawer, or a safe.

<Aside type="caution">
  The Emergency Recovery Kit is the only way back into your account if you lose the master password. Vautr cannot reset it for you, because the server holds no key material that can decrypt your vault.
</Aside>

## 4. Create a project and a secret

Vautr organizes secrets into projects. Create your first project:

```bash
cargo run -p vautr-cli -- create project "Demo" --description "Secrets for my side project"
```

Note the project UUID in the output. Create a secret inside it — omit `--value` and the CLI reads the plaintext from standard input, so the secret stays out of your shell history:

```bash
cargo run -p vautr-cli -- create secret API_KEY --project <uuid>
```

The client encrypts the secret with XChaCha20-Poly1305 before it leaves your machine. The server stores ciphertext only.

## 5. Retrieve and use the secret

List what you have stored:

```bash
cargo run -p vautr-cli -- list
```

Reveal a secret's plaintext by key:

```bash
cargo run -p vautr-cli -- get API_KEY
```

The most useful command is `run`: it resolves secrets and injects them into the environment of any command you execute:

```bash
cargo run -p vautr-cli -- run -- printenv API_KEY
```

## 6. Log out

Clear the stored session when you finish:

```bash
cargo run -p vautr-cli -- logout
```
