## What to build

Enhance `GET /sync/pull` to support pagination:
- Query parameters: `cursor` (u64, required), `limit` (u32, max 1000, default 100).
- Response includes `new_cursor` and `has_more` flag.
- Server must use indexed cursor (e.g., `WHERE version > cursor ORDER BY version LIMIT limit`).
- Client automatically loops until `has_more == false`.

## TDD Instructions

1. **Write a test** that creates 500 items, then pulls with `limit=100`; assert it returns 100 items, `has_more=true`, and the next cursor is higher.
2. **Write a test** that continues pulling until `has_more=false` and verifies all 500 items are received.
3. **Write a test** that uses a stale cursor (e.g., cursor that points to a version no longer in the DB because of pruning) – server returns 410.
4. **Write a test** that requests `limit=2000` – server returns 400 `payload_limit_exceeded`.
5. **Write a test** that measures the time to pull 10,000 items with limit=1000 – must be < 2 seconds.

Implementation: use `sqlx::query_as` with `OFFSET` is not efficient; use `WHERE version > cursor` and index on `(user_id, version)`.

## Acceptance criteria

- [x] Client respects `has_more` and does not hammer the server. (verified: `pagination_walks_500_items` loops on `has_more` until false)
- [x] Server response time is linear with `limit`, not with total item count. (verified: `pull_10k_items_under_two_seconds` — 10k items @ limit=1000 in < 2s; uses `WHERE version > cursor` indexed scan)
- [x] Cursor expiration (410) forces client to full resync. (verified: `expired_cursor_returns_410` → 410 `cursor_expired`; `cursor_within_window_succeeds_after_pruning` → ok)

## Implementation notes

- `GET /sync/pull` already enforces: required `cursor`, `limit` default 100 / max 1000 (400 `payload_limit_exceeded` when 0 or >1000), `new_cursor` + `has_more`, indexed `WHERE version > cursor ORDER BY version LIMIT ?`, and 410 `cursor_expired` when the cursor precedes the oldest retained version (pruned history).
- Tests added in this pass (TDD #1 strict cursor-advance + TDD #5 perf) bring coverage to the five TDD scenarios. The handler code itself was already in place (VTR-018 follow-through).
