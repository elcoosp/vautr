## What to build

UniFFI bindings for `vautr-core` exposing:
- `VautrClient` methods (excluding `read_secret` – gated).
- `SecretHandle` as `UInt64` (pass to Kotlin/Swift).
- Platform adapter implementation in Kotlin (Android) and Swift (iOS) that calls `perform_action` and directly uses OS clipboard APIs.

Native overlay component (SwiftUI / Android View) that renders decrypted text for a given handle without passing it to the React Native bridge.

## TDD Instructions

1. **Write a Kotlin test** that initialises `VautrClient`, calls `reveal_secret`, then `perform_action(CopyToClipboard)`, and asserts the Android clipboard contains the expected string.
2. **Write a Swift test** (XCTest) that does the same on iOS.
3. **Write a test** that reveals a secret, rotates the device (triggers a view lifecycle), and asserts `release_secret` is called (via a spy in the test harness).
4. **Write a test** that ensures the `read_secret` method is **not** present in the generated Kotlin/Swift code (compile‑fail test).
5. **Write an integration test** using Maestro that launches the React Native app, logs in, copies a password, and verifies the clipboard content.

Implementation: `uniffi.toml` configuration, generate bindings via `uniffi-bindgen`, and wrap them in a Turbo Module for RN.

## Acceptance criteria

- [ ] The Kotlin/Swift bindings compile without errors.
- [ ] No JS string ever holds the password.
- [ ] The native overlay component renders directly from the handle without copying.
