## What to build

A generic function `hkdf_derive(ikm: &[u8], salt: &[u8], info: &[u8], output_len: usize) -> Zeroizing<Vec<u8>>` using HKDF‑SHA256. Then wrapper functions:
- `derive_kek(mk: &MasterKey) -> KEK`
- `derive_oek(svk: &SymmetricVaultKey) -> Zeroizing<[u8; 32]>`
- `derive_dek(svk: &SymmetricVaultKey) -> Zeroizing<[u8; 32]>`

## TDD Instructions

1. **Write a test** that calls `hkdf_derive` with the same IKM, salt, info, and length twice; asserts outputs are equal.
2. **Write a test** that uses different info strings and asserts outputs are different.
3. **Write a test** for `derive_kek` that derives a 32‑byte key from a fixed master key; assert it matches a pre‑computed test vector (use known answer from spec).
4. **Write a test** that derives OEK and DEK from the same SVK and asserts they are different (key separation).
5. **Write a property‑based test** that ensures `hkdf_derive` never panics for any valid length (1..1024).

Implementation uses `hkdf::Hkdf<Sha256>` and `expand`. The salt must be a fixed string per derivation: `"vautr-kek-salt"`, `"vautr-oek-salt"`, `"vautr-dek-salt"` as bytes.

## Acceptance criteria

- [ ] All tests pass.
- [ ] Output length can be any `usize` (test 16, 32, 64).
- [ ] The functions are zero‑allocation (except the output vector).
