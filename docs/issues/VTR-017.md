## What to build

Two new tables:
- `sync_meta` (singleton) with `id INTEGER PRIMARY KEY`, `sync_cursor INTEGER`, `min_enc_key_gen INTEGER`, `svk_ciphertext_blob BLOB`.
- `local_blacklist` with `uuid TEXT PRIMARY KEY`, `ignored_version INTEGER`, `state TEXT CHECK(state IN ('ToxicIgnored','ValidIgnored'))`.

Plus a function `persist_dashmap(entries: Vec<LocalBlacklistEntry>)` that atomically wipes and rewrites the entire `local_blacklist` table.

## TDD Instructions

1. **Write a test** that inserts a few entries into `local_blacklist`, then calls `persist_dashmap` with a new set; assert old entries are gone and new ones exist.
2. **Write a test** that updates `sync_meta` with a new cursor and verifies reading back the same value.
3. **Write a test** that attempts to insert an invalid state ('InvalidState') and expects a constraint violation.
4. **Write a test** that uses a transaction to ensure atomicity: simulate a crash after wipe but before rewrite – the table must be empty (rollback).

Implementation: SeaORM `delete_many()` + `insert_many()` in a single transaction.

## Acceptance criteria

- [ ] Atomic wipe+rewrite is used by the sync engine to persist the DashMap.
- [ ] No `is_dirty` flag needed – entire table is snapshot.
- [ ] `sync_meta` is guaranteed to have exactly one row (id=1).
