## What to build

A `SyncEngine` component (in `vautr-sync`) with method `pull_metadata(cursor: u64) -> Result<SyncPullResponse, CoreError>` that:
- Calls `GET /sync/pull` on the server.
- Filters returned items against an in‑memory `DashMap` (loaded from `local_blacklist` table).
- Returns only metadata for items **not** in the blacklist (or with version > ignored_version).
- Updates local `sync_cursor` and `min_enc_key_gen`.

## TDD Instructions

1. **Write a test** using `wiremock` that returns 3 metadata items. Initialize an empty `DashMap`. Assert that all 3 are returned.
2. **Write a test** where one item is in the DashMap with `ignored_version=5` and server version is 5; assert that item is filtered out.
3. **Write a test** where server version (6) > ignored_version (5); assert item **is** returned (ignored only if version <= ignored).
4. **Write a test** that checks `min_enc_key_gen` from server is stored in `sync_meta` and exposed.
5. **Write a concurrency test** (using `loom` model) that simulates multiple threads reading the DashMap while the sync engine is filtering – no panics.

Implementation: `DashMap<Uuid, DashMapEntry>` must be loaded from DB at startup. Filtering is O(1) per item.

## Acceptance criteria

- [ ] All tests pass.
- [ ] The DashMap is shared via `Arc` and can be read concurrently.
- [ ] If cursor expires (410), the engine returns `CoreError::SyncResetRequired`.
