## What to build

Web and extension currently reveal secrets by decrypting on the JS main thread
and holding plaintext in component state (`apps/web`, `apps/extension`). This is
acceptable because the server is the trust root for those clients, but it is not
parity with desktop's native-overlay model.

For full ZK parity:
- Decrypt in the WASM core (`vautr-ffi` wasm target) so the plaintext never
  crosses into JS except as an opaque handle / ephemeral buffer.
- Bind the decrypted bytes to the DOM only for the duration of the reveal
  interaction (copy / autofill / overlay), then zero them.
- Reuse the `SecretOverlay` pattern already proven on mobile/desktop.

Lower priority than VTR-061 — web is the reference client and explicitly
server-trusted, so this is hardening rather than a correctness gap.

## Acceptance criteria

- [ ] Decrypt happens in WASM, not JS.
- [ ] Plaintext is zeroed after reveal interaction.
- [ ] No plaintext in React/extension state during normal reveal.
