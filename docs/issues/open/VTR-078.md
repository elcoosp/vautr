# VTR-078 — True element-anchored tour (mobile + desktop)

VTR-077 shipped the feature tour as *centered-card sequences* on mobile (RN) and
desktop (GPUI) because neither framework exposes an element-measurement
primitive the way web/extension do (`getBoundingClientRect` + `[data-tour]`).

This follow-up upgrades those two clients to **true spotlight anchoring**:
- **Mobile (RN):** measure the target element with
  `ref.measure(callback)` / `onLayout` and position a highlight overlay +
  tooltip above the real control (Vault tab, + Add, MFA, Audit nav).
- **Desktop (GPUI):** use `bounds()` on the target element (GPUI elements are
  layout-aware) to compute a highlight rect + positioned card, matching the
  web/extension anchored tour.

The shared step contract stays `docs/onboarding/tour.md`. The centered-card path
remains the graceful fallback if measurement is unavailable.

## Acceptance
- Mobile + desktop tours highlight the actual target control, not a centered card.
- Skip / Back / Next / Finish still work; replay affordance unchanged.
- `hermes verify` green; `cargo test` / `tsc` / `cargo fmt --check` / `pnpm lint` clean.
