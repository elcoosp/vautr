# VTR-075 — First-run guided onboarding (desktop)

## Context
Web + extension have first-run guided onboarding (VTR-073) via OnboardJS — a
headless multi-step flow engine. The desktop client (`apps/desktop`, Rust + GPUI)
**cannot** use OnboardJS (JS/React library, can't run in the Rust process). The
user-approved approach: a faithful **native Rust re-implementation of the flow**
that produces the *same UX* (same 5 steps, copy, skippable behaviour, first-run-once
+ replay) using GPUI widgets + `theme.rs`.

The shared contract lives in `docs/onboarding/spec.md` — implement against it.

## What to build
- New module `apps/desktop/src/onboarding.rs` (or `crate::onboarding`):
  - Step model mirroring the spec: `welcome`, `create-vault`, `emergency-kit`,
    `add-secret`, `done`. Each has `id`, `title`, `body`, `skippable`, and a
    `cta` descriptor (label + action).
  - A small flow state machine: `current_index`, `next()`, `previous()`, `skip()`,
    `is_completed`, `progress()` (N of 5). No async engine needed — pure state.
- First-run persistence: a tiny struct `{ seen_v1: bool }` serialized as JSON to
  `~/.config/vautr/onboarding.json` (resolve home via `std::env::var("HOME")` or
  `dirs`-like; create the dir if missing). Use `serde` + `serde_json` (already
  deps). `load()` reads it; `mark_seen()` writes it. On app-shell render, if
  `!seen_v1`, show the overlay; on finish/skip-to-end, `mark_seen()`.
- Rendering: a GPUI **modal overlay** (absolute layer above the app shell) using
  existing `gpui-component` widgets (`v_flex`, `h_flex`, `Button`, `InputState`,
  `Icon`/`IconName`) + `theme.rs` colors (`theme::SURFACE`, `theme::BORDER`,
  `theme::TEXT`, `theme::TEXT_MUTED`, `theme::ACCENT`). One centered `Card`-like
  container showing the current step's title/body, a progress line ("Step N of 5"),
  and Back / Next / Skip buttons driven by the flow state machine.
- Actions wire to real surfaces (no stubs):
  - `create-vault`: call the existing client `create_project(...)` (api_client has
    it) with name "My Vault"; on success advance.
  - `emergency-kit`: open the Settings section (the existing `Section::Settings`
    / recovery surface).
  - `add-secret`: open the Vault / Secrets section.
- Replay: a "Replay onboarding" entry in the desktop Settings section that clears
  the flag (`seen_v1 = false`) and re-shows the overlay.

## Hard rules (from spec)
- No stubs: CTAs drive real client APIs / sections.
- ZK preserved: flow only navigates/creates; no secret plaintext rendered.
- First-run only; replay clears the flag.
- Step copy is the contract in `docs/onboarding/spec.md` — keep identical.

## Acceptance criteria
- [ ] `crate::onboarding` module with the 5 steps + flow state machine (pure Rust).
- [ ] First-run flag persisted to `~/.config/vautr/onboarding.json`; overlay shows
      once; never blocks on subsequent launches.
- [ ] GPUI modal overlay renders the steps with theme.rs styling; Next/Back/Skip
      (skip on steps 3 & 4); Finish on step 5.
- [ ] CTAs drive real surfaces (create_project; open Settings/Vault sections).
- [ ] "Replay onboarding" in Settings clears the flag and re-runs.
- [ ] `cargo check -p vautr-desktop` + `cargo fmt -p vautr-desktop` clean; `hermes
      verify --json` stays green.

## Verification
- `cargo check -p vautr-desktop` (sccache disabled) clean.
- `cargo fmt -p vautr-desktop --check` clean.
- `hermes verify --json` → `ok: true`.
- Manual (desktop): fresh config (no onboarding.json) → overlay appears on unlock;
  complete → file written `seen_v1: true`; relaunch → no overlay; Settings →
  Replay → overlay returns.
