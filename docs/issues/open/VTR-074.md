# VTR-074 — First-run guided onboarding (mobile)

## Context
Web + extension have a first-run guided onboarding flow (VTR-073) built on
OnboardJS. Mobile (Expo SDK 57 / RN 0.86 / nativewind 4.2.6) is also React, so it
can reuse the **same engine and step definitions** — only the step components are
restyled with nativewind (className) instead of shadcn, and persistence uses
AsyncStorage (no browser localStorage in RN).

The shared contract (steps, copy, CTAs, skippability) lives in
`docs/onboarding/spec.md` — implement against it, do not diverge.

## What to build
- Add `@onboardjs/core` + `@onboardjs/react` (pinned RCs: core `1.0.0-rc.4`,
  react `1.0.0-rc.5`, matching web/ext) to `apps/mobile/package.json`.
- Add `@react-native-async-storage/async-storage` (Expo-compatible) for the
  first-run flag.
- `apps/mobile/src/onboarding/steps.tsx`: same 5 steps as the spec
  (welcome → create-vault → emergency-kit → add-secret → done). Step components
  use nativewind className styling and RN primitives (View/Text/TextInput/Pressable
  or the app's ui components). `create-vault` calls `mlp.createProject`; `emergency-kit`
  / `add-secret` navigate via the TanStack Router `useNavigate` to the mobile
  settings / secrets routes.
- `apps/mobile/src/onboarding/OnboardingFlow.tsx`: `OnboardingProvider` with
  `customOnDataLoad` / `customOnDataPersist` wired to AsyncStorage key
  `vautr_onboarding_v1` (instead of `localStoragePersistence`). Renders a centered
  overlay (RN Modal / absolute overlay) with the current step + Next/Back/Skip
  chrome. `triggerReplayOnboarding()` clears the AsyncStorage key + dispatches a
  reset event.
- Mount `OnboardingFlow` at the mobile app root (`App.tsx` / router root) wrapping
  the app shell.
- Replay affordance: a "Replay onboarding" entry in the mobile Settings screen
  (`_app.settings.tsx`) calling `triggerReplayOnboarding()`.

## Hard rules (from spec)
- No stubs: CTAs drive real surfaces (createProject; navigate to settings/secrets).
- ZK preserved: flow only navigates / calls existing client APIs.
- First-run only; replay clears the flag.
- Step copy is the contract in `docs/onboarding/spec.md`.

## Acceptance criteria
- [ ] `@onboardjs/*` + `async-storage` installed in mobile (pinned RCs).
- [ ] Flow shows once (AsyncStorage flag) after first register/login; never blocks
      the app on subsequent loads.
- [ ] Same 5 steps + copy + skippable behaviour as the spec; real CTAs.
- [ ] "Replay onboarding" in Settings clears state and re-runs.
- [ ] `pnpm -r typecheck` (mobile) and `pnpm test` green; `hermes verify --json`
      stays green (web/ext/desktop unchanged but must remain green).

## Verification

- `hermes verify --json` → `ok: true`.
- Manual: clear AsyncStorage `vautr_onboarding_v1`, register, confirm flow appears;
