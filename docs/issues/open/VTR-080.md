# VTR-080 — Dark-mode accent is red, not emerald

## Problem
In dark mode the web (and desktop/mobile via the shared token pipeline) primary
accent rendered pure red `#ff0000` instead of the intended emerald/teal. The
build script maps `color.accent → --primary`, and `tokens.json` had
`color.accent.$value.dark = "#ff0000"`. Light mode was already correct
(`#1f8f74`).

## Fix
Set `color.accent.$value.dark` to `#42b59a` (the emerald/teal used by
`sidebar-primary` / `ring`), matching the intended brand. Regenerated all token
artifacts via `pnpm --filter @vautr/design-tokens build:tokens`:
`tokens.css`, `tokens.rs`, `tokens.ts`, `vautr-theme.json`, `tokens.md`, and the
committed desktop `apps/desktop/src/theme_tokens.rs` + `apps/desktop/src/vautr-theme.json`.
Confirmed `--primary: #42b59a` (dark) / `#1f8f74` (light).

## Verification
- `pnpm --filter @vautr/design-tokens build:tokens` regenerates cleanly.
- `grep -- "--primary" packages/design-tokens/tokens.css` → `#42b59a` / `#1f8f74`.
- `apps/web` `pnpm build` + `tsc --noEmit` green.
- `hermes verify --json` green.

## Acceptance
Dark mode accent is emerald on web/desktop/mobile; no red primary anywhere.
