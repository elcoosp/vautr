# VTR-071 — Audit-log viewer + export in clients

## What to build
The server already exposes `GET /audit` (admin) backed by the `audit_log` table
(`core/vautr-server/src/handlers/audit.rs`, `repository::audit`, `AuditFilter`),
recording login/logout/account-deletion/key-rotation metadata (VTR-053). But **no
client surfaces it** — a grep of `apps/web/src` and `apps/desktop/src` for audit
export returns zero matches. The user cannot see or export their own security
timeline.

Implement a client-side audit surface:
- **Web** (`apps/web`): a "Security log" route/panel calling `mlp.auditList()`
  (paged `GET /audit`), rendering events (actor, action, timestamp) and a
  "Download JSON" button.
- **Desktop** (`apps/desktop/src/desktop_view.rs`): a "Security log" section
  (admin-gated) listing events and an export-to-file action, mirroring the vault
  export pattern already in `do_export_vault`.
- **SDK** (`packages/vautr-client-sdk`): add `auditList(filter?, limit?, offset?)`
  to the MLP client (the `/audit` contract already exists in
  `packages/api-contract`).

## Zero-knowledge note
Audit events are **metadata only** (who/what/when), never secret plaintext
(VTR-053). Surfacing them client-side is ZK-safe; do NOT include decrypted
overviews/secrets in the export.

## Acceptance criteria
- [ ] `mlp.auditList()` exists in the SDK and returns the `GET /audit` contract shape.
- [ ] Web "Security log" lists events with pagination and offers JSON download.
- [ ] Desktop "Security log" lists events (admin-gated) with export-to-file.
- [ ] Export contains only metadata fields, no secret bytes.
- [ ] `pnpm -r typecheck` and `hermes verify --json` stay green.

## Verification
- SDK unit test: `auditList()` round-trips the contract type.
- Web: vitest component test renders a mocked event list + exercises download.
- Desktop: `cargo check -p vautr-desktop` clean.
- `hermes verify --json` → `ok: True`.
