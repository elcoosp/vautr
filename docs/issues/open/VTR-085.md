# VTR-085 — Desktop `register/finish` / `login` "parse error decoding response body"

**Status:** fixed (pending commit)
**Date:** 2026-08-15
**Client:** desktop (`apps/desktop/src/auth_client.rs`)

## Symptom
User: "registration failed on desktop register/finish parse: error decoding
response body". The desktop auth client showed a cryptic parse error instead of
the real server reason.

## Root cause
`auth_client.rs` `register()` and `login()` built requests with the raw
`self.client.post(...).send().await?.json().await?` pattern. They parsed the
response body **without checking the HTTP status code**. On any non-2xx response
(e.g. a transient 500 during a server restart / flap, or a real 4xx/5xx), reqwest
tried to deserialize an error/HTML body as `RegisterFinishResp` and failed with a
bare "parse error decoding response body" — hiding the actual cause.

The sibling `ApiClient::send` (api_client.rs) already does the correct thing
(status gate + error-envelope extraction); the auth client just didn't use it.

## Fix
Added a `send_json<T>(resp)` helper to `auth_client.rs` that:
- reads the raw bytes,
- on non-2xx returns `HTTP {code}: {error}: {message}` using the server's
  `ErrorEnvelope` when present (falls back to the raw body),
- on success deserializes as before.

Wired `register` (register/start, register/finish) and `login` (login/start,
login/finish, account/status) through it. Now a server error surfaces as e.g.
"HTTP 500: internal_server_error: ..." instead of "parse error decoding response body".

## Verification
- `cargo check` green (RC=0; only pre-existing unused-import warnings).
- `cargo build` green.
- `register_and_login_roundtrip` test passes against the live server (200s).
- Server is stable via launchd; only historical 500 (during earlier restarts) in log.
- hermes verify green.

## Note
The cryptic message was a *client* masking bug, not a server contract bug. The
server returned valid JSON for register/finish (confirmed by CLI + desktop roundtrip).
If the user still hits a real server 500, the message will now name it clearly.
