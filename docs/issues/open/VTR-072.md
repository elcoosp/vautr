# VTR-072 — Complete VTR-060 self-hosting documentation

## Context
VTR-060 ("Self-hosting documentation") is marked `status: done (2026-08-13)` but
its acceptance criteria are **unchecked** and its concrete deliverables are
**absent from the tree**:
- `docs/self-hosting/` directory — does not exist.
- `docker-compose.prod.yml` (healthchecks + restart policies) — does not exist.
- `docker-compose.yml` (base) and `Dockerfile` DO exist at repo root, and
  `scripts/install.sh` / `scripts/update.sh` exist, but there is no written
  runbook tying them together.

This issue closes that gap so the self-hosting promise ("forever free to
self-host") is actually documented and reproducible.

## What to build
- `docs/self-hosting/README.md`: step-by-step quick start
  (`docker compose up -d`), environment-variable reference
  (`DATABASE_PATH`, `RUSTFS_ENDPOINT`, `RATE_LIMIT_REDIS_URL`, `SMTP_*`),
  backup/restore (`sqlite3 .backup` + volume snapshots), upgrade procedure
  (DB auto-migrates), and reverse-proxy (Caddy/Nginx + HTTPS) guidance.
- `docker-compose.prod.yml`: production variant with healthchecks and
  `restart: unless-stopped`, optional Redis + backup sidecar (litestream).
- Keep the existing root `docker-compose.yml` as the dev/simple variant.

## Acceptance criteria (carries VTR-060's unchecked items)
- [ ] A technical user can stand up a production server in < 15 minutes using the docs.
- [ ] Docs cover backup/restore and upgrade with no data loss.
- [ ] Server runs behind Caddy/Nginx with automatic HTTPS per the guide.
- [ ] `docs/self-hosting/` and `docker-compose.prod.yml` exist and are linked from root README.

## Verification
- Manual: follow `docs/self-hosting/README.md` on a clean VM; `docker compose up -d`;
  connect a client, create a vault, add an item — all work.
- `docker compose -f docker-compose.prod.yml config` validates without error.
- Link-check: root README references the new docs path.
