# VTR-083 — Onboarding runs without a session → "missing or expired session" on Create vault

**Status:** fixed (pending commit)
**Date:** 2026-08-15
**Clients:** web, mobile, extension (desktop already gated via `is_unlocked()`)

## Symptom
During first-run onboarding, clicking **Create vault** failed with:

```
POST http://localhost:8080/projects → 401
missing or expired session
```

The flow also showed before the user could navigate the app, which is contradictory:
you cannot use the app (or create a vault) without being logged in.

## Root cause
`OnboardingFlow` was mounted **unconditionally** in each client's entry point. It only
checked `localStorage`/`AsyncStorage` persistence, never whether a session existed.
So onboarding appeared pre-login and its first step (`createProject`) hit the server
with no bearer token → `401 unauthorized` ("missing or expired session").

`register()` deliberately does **not** mint a session (it sets `sessionToken: null`);
only `login()` does. The web already auto-logs-in after register
(`register.tsx: await login(...)`), so once we gate onboarding on an active session the
"create vault at registration" path works because the user *is* authenticated at that
point.

## Fix
Gate `OnboardingFlow` on a live session in all three JS/TS clients:
- **web**: new `apps/web/src/lib/useSession.ts` (reactive read of
  `IndexedDbStore.getState().sessionToken`, refreshed on focus + a `vautr:auth-change`
  event). `OnboardingFlow` returns `children` until `useSession()` is true. `client.ts`
  `login()` now dispatches `vautr:auth-change`.
- **mobile**: gate on `useSession((s) => s.username)` (non-null = logged in).
- **extension**: gate on `usePopupStore((s) => s.status === 'unlocked')`.
- **desktop**: already gated via `is_unlocked()` in `desktop_view.rs` — no change.
