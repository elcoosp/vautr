# VTR-082 — Onboarding steps crash on `useNavigate()` outside the RouterProvider

**Status:** fixed (pending commit)
**Date:** 2026-08-15
**Clients:** web (also mobile/extension share the same step structure)

## Symptom
The first-run onboarding flow rendered a red error screen. Console showed:

```
Warning: useRouter must be used inside a <RouterProvider> component!
TypeError: Cannot read properties of null (reading 'navigate')
    at onClick (steps.tsx:138 / steps.tsx:166)
```

Clicking the deep-link buttons (`Open security settings`, `Go to my vault`) and the
`Create vault` submit threw because `useNavigate()` returned `null`.

## Root cause
`OnboardingFlow` wraps `<RouterProvider>` in `main.tsx`, so OnboardJS renders the
custom step components **outside** the router React context. `useNavigate()` from
`@tanstack/react-router` only works inside the provider, so it returned `null` and
calling `.navigate()` on it crashed.

This was exposed by the VTR-081 fix: once `componentRegistry` made the steps actually
render, the previously-dead `useNavigate()` calls started executing.

## Fix
- `apps/web/src/onboarding/steps.tsx`: removed `useNavigate`; the three navigation
  actions now call the exported `router.navigate(...)` imperatively (works outside the
  React tree). `CreateVaultStep.createProject` + navigate, `EmergencyKitStep` →
  `/settings`, `AddSecretStep` → `/projects`.
- Verified: Vite serves `router.navigate` ×3, `useNavigate` ×0; `tsc --noEmit` clean.
