# VTR-079 — Desktop app aborts on fresh launch

## Problem
`apps/desktop` panics on a **fresh** launch with:

```
thread 'main' panicked at 'this method can only be called during paint',
crates/gpui/src/window.rs:4964
```

Stack: `app::run` → `App::open_window` → `DesktopView::new` → `on_key_event`'s
`debug_assert_paint`. The crash only fires when `~/.config/vautr/onboarding.json`
does not yet exist (first run), because that path executes `new()` which called
`window.on_key_event(...)` during view construction — outside GPUI's paint phase.

This is pre-existing (committed in `696ecca feat: ui ux unification`), surfacing
now that the desktop actually launches for UI review.

## Fix
GPUI permits `on_key_event` registration only during the paint phase. Moved both
window-level handlers (escape-to-close modal, idle auto-lock activity clock) out
of `DesktopView::new()` into the paint closure of the existing `canvas` element in
`render_app`, guarded by a one-time `key_handlers_registered` flag. Added the flag
field + `Self {}` init.

## Verification
- `cargo check -p vautr-desktop` green (no `^error`).
- App launches and stays alive (PID observed running >60s, no panic).
- `hermes verify --json` green.

## Acceptance
Desktop launches on a fresh profile without the `debug_assert_paint` panic.
