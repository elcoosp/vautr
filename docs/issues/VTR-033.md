## What to build

Server endpoints:
- `DELETE /account` (authenticated): immediately deletes all user data (items, wrapped SVKs, OPAQUE record, public key).
- `POST /account/reclaim/initiate` (unauthenticated): sends verification email; generates a reclaim token.
- `POST /account/reclaim/complete` (with token): suspends the old account (sets `suspended_at`), releases the email for new registration, and schedules permanent deletion after 30 days.
- Background job that purges suspended accounts after 30 days.

## TDD Instructions

1. **Write a test** that creates an account, then calls `DELETE /account` authenticated – asserts all user rows are removed from `items` and `users` tables.
2. **Write a test** that initiates reclaim for an email, clicks the verification link, and completes reclaim – asserts the email can be used to register a new vault immediately, and the old vault data is still present but suspended.
3. **Write a test** that after 31 days (using mocked time), the suspended account’s data is permanently purged.
4. **Write a test** that tries to reclaim an email that does not exist – returns 404.
5. **Write a test** that attempts to complete reclaim with an expired token (e.g., after 24 hours) – returns 401.

Implementation: add `suspended_at` and `purge_scheduled_at` columns to `users` table. Use `sqlx` and a `tokio::task` for periodic cleanup.

## Acceptance criteria

- [ ] Reclaim does **not** require the old MP or RK – only email access.
- [ ] The 30‑day suspension gives the user a window to recover if email was compromised.
- [ ] All deletion endpoints are idempotent.
