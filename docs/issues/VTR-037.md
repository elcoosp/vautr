## What to build

Extend the nightly CI pipeline to include:
- `cargo-fuzz` targets for `aead_decrypt` (ensuring no panics on arbitrary input) – runs for 1 hour.
- Memory leak test using a custom `Drop` counter for `Zeroizing<String>` – after a stress test, the counter must return to baseline.
- Pact contract tests between the TypeScript SDK (`vautr-client-sdk`) and the server, ensuring the API matches the OpenAPI spec.

## TDD Instructions

1. **Write a fuzz target** that feeds random bytes to `aead_decrypt` and asserts it never panics (returns `Err` gracefully). Run it locally with `cargo fuzz run` and verify it passes for 1 hour.
2. **Write a memory leak test** that reveals and copies 10,000 secrets in a loop, then forces a GC and checks the `Zeroizing` drop counter returns to 0.
3. **Write a Pact test** (consumer side in TypeScript) that defines an interaction for `POST /sync/push-batch`, then runs the provider (server) against it – must pass.
4. **Write a CI job** that fails if any `cargo-fuzz` regression is found (using a corpus).
5. **Write a test** that ensures the `test-instrumentation` feature does not leak into production builds (compile‑fail check).

Implementation: add `fuzz/` directory with targets. Use `cargo test --features test-instrumentation` for drop counters. Pact can be run with `pact-rust` and `pact-js`.

## Acceptance criteria

- [ ] Nightly CI runs fuzzing and fails if a crash is found.
- [ ] Memory leak test passes consistently.
- [ ] Pact contract tests prevent API drift.
