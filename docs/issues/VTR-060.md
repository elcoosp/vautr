## What to build

Comprehensive self‑hosting guide:
- `docker-compose.yml` with `vautr-server`, SQLite volume, optional Redis, and a backup sidecar (e.g., litestream).
- Environment variables reference: `DATABASE_PATH`, `RUSTFS_ENDPOINT`, `RATE_LIMIT_REDIS_URL`, `SMTP_*` for email reclaim.
- Backup and restore instructions (using `sqlite3 .backup` and file system snapshots).
- Quick start guide: `curl -O https://vautr.com/docker-compose.yml && docker compose up -d`.
- Minimum hardware requirements (1 vCPU, 1GB RAM).

## TDD Instructions

This is documentation – verification is manual:

1. **Test the docker‑compose.yml** on a fresh Ubuntu 22.04 VM: run `docker compose up -d`, then connect a client, create a vault, add an item – all must work.
2. **Test backup**: stop the server, run `docker exec vautr-server sqlite3 /data/vautr.db ".backup /backup/vautr.db.backup"`, then restore to a new VM and verify data integrity.
3. **Test email reclaim**: configure SMTP (using a test mailhog), trigger account reclaim, receive the email, complete reclaim – works.
4. **Test upgrade**: replace the Docker image tag with a newer version, restart – the database migrates automatically (no data loss).
5. **Test resource limits**: run the server on a Raspberry Pi 3 with 1GB RAM and 100 items; verify sync and search are responsive.

Implementation: write markdown files in `docs/self-hosting/` with step‑by‑step instructions. Include a `docker-compose.prod.yml` with healthchecks and restart policies.

## Acceptance criteria

- [ ] A technical user can set up a production server in < 15 minutes.
- [ ] The documentation includes backup/restore and upgrade procedures.
- [ ] The server can be run behind a reverse proxy (Caddy, Nginx) with automatic HTTPS.
