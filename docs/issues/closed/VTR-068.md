# VTR-068 — Group sharing (1:N zero-knowledge relay)

Extends the ADR-007 sharing PKI to groups (sharing-pki.md §6): one admin creates a
group, wraps the unified Group SIK per member, and any holder encrypts an item
**once** under the Group SIK; members unwrap the SIK and decrypt locally. The
server is an untrusted relay — it only stores the per-member KEM wraps and the
Group-SIK-encrypted item payloads.

## What was built

- **Group crypto (`vautr-sharing`):** `ShareGroupKey` made stateless-FFI friendly
  via `secret_bytes()` / `from_secret()` (mirrors `SharingKeyPair`). The existing
  `create_group`, `add_group_member`, `unwrap_group_key`, `encrypt_item`,
  `decrypt_item`, `rotate_group_sik` are unchanged in behavior — only the secret
  export was added so the wasm FFI (which holds group state in JS) can reconstruct
  the key between calls.
- **Server — missing group-item delivery (the gap):** new migration
  `0014_group_items_payload.sql` adds `payload BLOB` to `group_items`;
  `repository/sharing.rs` `add_group_item` now stores the payload,
  `list_group_items` returns `(item_uuid, payload)`, and a new `delete_group_item`
  was added. New handlers: `POST /groups/{group_id}/items`,
  `GET /groups/{group_id}/items`, `DELETE /groups/{group_id}/items/{item_uuid}`
  (admin-only, auth-enforced). The group *key-management* endpoints
  (`POST /groups/`, members, rotate, `/groups/inbox`) already existed.
- **wasm FFI (`vautr-wasm`):** `create_sharing_group`, `add_group_member`,
  `unwrap_group_key` (takes the full group-inbox entry + caller secret),
  `encrypt_group_item`, `decrypt_group_item` — all stateless, returning/accepting
  the `{ group, secret }` ShareGroupKey JSON. `wasm-pkg` rebuilt.
- **SDK:** `VautrMlpClient` 9 group methods; `VautrWebClient` `GroupManager`
  (`createGroup`, `addGroupMember`, `getGroupInbox`, `unwrapGroupKey`,
  `shareItemToGroup`, `getGroupItems`, `acceptGroupItem`, `revokeGroupItem`,
  `rotateGroup`, `removeGroupMember`, `getGroupKey`); `groupKeys` map persisted in
  `StoredState`; `AsyncCryptoAdapter` + `vautr-wasm.d.ts` + `wasmWeb.ts` +
  `mockWasm.ts` declarations.
- **Extension UI:** new `GroupsTab` (create, add member, unwrap key, list/decrypt/
  revoke group items) wired into the popup tab strip.
- **Web UI:** new `GroupsView` (same flow) on a "Groups" tab; `ItemDetail` share
  dialog now also offers "share into a group" (lists the caller's admin groups).
- Server `group_add_and_member_inbox` e2e test now also exercises item delivery.

## Zero-knowledge invariant

As with 1:1 sharing, the server stores only KEM envelopes + DEM ciphertext for
group items. Group SIKs are wrapped per member under their sharing public key; a
member's plaintext never reaches the server. Decryption happens entirely in wasm.

## Verification gaps / notes

- Mobile group sharing is **out of scope here** — it requires the uniffi native
  bridge (`VTR-070` track). The desktop/mobile ZK invariant (plaintext must not
  enter JS) is preserved: all decryption is in wasm.
- The "share item to group" entry point is wired in the **web** `ItemDetail`
  dialog; the extension `GroupsTab` lists/decrypts items but does not yet expose a
  per-item "share into group" button from the vault item view (admins can still add
  items via the existing item share + group membership). Follow-up if desired.
