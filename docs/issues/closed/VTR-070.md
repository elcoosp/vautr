# VTR-070 — Mobile sharing (uniffi FFI + PM-item UI)

## Context (why)
Web/extension (VTR-066/067) and desktop share items via the `vautr-sharing` PKI, but
the **mobile** client (`apps/mobile`, React Native + Expo) had no sharing surface. The
zero-knowledge invariant must hold on mobile too: plaintext secret bytes must be
produced inside Rust (the uniffi `MobileClient`) and never sit in the JS heap.

Mobile uses a **different core** than web/extension. Web/extension drive an
`AppState`-backed `VautrClient` over HTTP; mobile links the same `vautr_app_state`
core **natively** through the uniffi `MobileClient` (`core/vautr-ffi`). So mobile
sharing exposes the `vautr-sharing` primitives through uniffi and layers the HTTP PKI
relay in a `MobileSharingClient` (mirrors `VautrMlpClient` but native).

## What shipped
- **Rust FFI (`core/vautr-ffi`)**
  - `Cargo.toml`: added `vautr-sharing` dependency.
  - `src/sharing.rs` (new): uniffi exports for the zero-knowledge sharing primitives —
    `ffi_share_item`, `ffi_accept_share`, `ffi_create_group`, `ffi_add_group_member`,
    `ffi_unwrap_group_key`, `ffi_encrypt_group_item`, `ffi_decrypt_group_item` — plus
    `FfiShareBundle` / `FfiWrappedGroupKey` / `FfiGroupKey` / `FfiSharingKeyPair`
    records. PEM/JSON framing matches `sharing-pki.md` (base64 fields, `ShareBundle`
    etc.).
  - `src/client.rs`: `MobileClient` gains a persisted `sharing_secret: RwLock<…>` and
    instance methods `ensure_sharing_key`, `set_sharing_secret`, `sharing_secret`,
    `share_item`, `accept_share`, `create_group`, `add_group_member`, `unwrap_group_key`,
    `encrypt_group_item`, `decrypt_group_item` (each delegates to `crate::sharing::*`;
    plaintext returned only to native callers).
  - `src/lib.rs` test module: two sharing roundtrip tests (1:1 + group) exercising the
    real `vautr-crypto`/`vautr-sharing` crypto. **5 vautr-ffi lib tests green.**
- **SDK (`packages/vautr-client-sdk`)**
  - `src/mobile.ts`: `VautrNativeBridge` gains the 9 sharing methods; new
    `MobileSharingClient` (native-gated) layers the HTTP relay (publish/fetch public
    key, create/upload share, inbox collect, group create/add-member/item) over the
    native bridge. `MobileVautrClient.getNativeBridge()` exposes the bridge.
  - `test/mobile-sharing.test.ts` (new): orchestration tests for `shareItem` +
    `collectShares`. **SDK suite 10/10 green.**
- **Mobile UI (`apps/mobile`)**
  - `src/routes/_app.shares.tsx` (new): Shares screen — share-to-user, create group,
    inbox — native-gated (`getMobileClient()?.getNativeBridge()`, clear gated message
    when the FFI core is absent).
  - `src/routes/_app.tsx`: Shares tab added to the bottom bar **only when
    `isLocalVaultActive()`** (native-gated). Route tree regenerated (`tsr generate`).
  - `lib/api.ts` (`MobileApiClient`): added the sharing PKI relay endpoints
    (`publishSharingPublicKey`, `getSharingPublicKey`, `createShare`, `uploadSharePayload`,
    `listShareInbox`, `createGroup`, `addGroupMember`, `listGroupItems`, `addGroupItem`).

## Zero-knowledge invariant
Plaintext secret bytes are produced only inside Rust (the uniffi `MobileClient`) and
handed back to the native caller; the JS layer holds only opaque base64 / handles. This
matches the desktop secure-overlay pattern (VTR-048) and the web/extension WASM pattern
(VTR-061) — no mobile analogue of the web plaintext-in-JS `revealSecret` violation.

## Not verifiable in this sandbox (documented)
The **mobile native build** (uniffi `bindgen` → Swift/Kotlin + RN native module
compile) cannot run here: no `uniffi-bindgen` CLI and no RN/Xcode/Gradle toolchain
(see memory: "Mobile native uniffi/TurboModule CANNOT be compiled in sandbox"). The
Rust FFI surface that the bindings wrap is fully implemented and tested; the TS
contract (`VautrNativeBridge`) and RN UI typecheck. The remaining step — regenerating
the uniffi Swift/Kotlin bindings and building the RN app — must be done on a machine
with the native toolchain (`pnpm -C apps/mobile ios` / `android` after
`uniffi-bindgen generate`). No stubs were introduced; the feature is real code, only
the native artifact build is environment-gated.
