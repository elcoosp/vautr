# VTR-066 — Extension sharing (send + receive + revoke)

Zero-knowledge 1:1 item sharing for the extension client, backed by the existing
server PKI (`POST /shares/`, `/shares/{id}/payload`, `/shares/inbox`, `DELETE
/shares/{id}`). The server is an untrusted relay: it only ever stores KEM
envelopes + DEM ciphertext.

## What was built

- **Crypto (Rust, `vautr-sharing` + `vautr-wasm`):** full share flow exposed to
  wasm — `generate_sharing_keypair`, `restore_sharing_keypair`, `share_item`
  (plaintext → `ShareBundle` base64 JSON: `wrapped_sik` + `ephemeral_public_key`
  + `encrypted_payload`), `accept_share` (inbox JSON → plaintext). A fresh random
  SIK is generated per share; the DEM associated-data is bound to `item_uuid`.
- **Server:** new `PUT /users/{id}/public-key` (enforces caller == user_id)
  backing the existing `upsert_sharing_public_key`. (`vautr_sharing::share_item`
  changed to key shares by `item_uuid` so the server's natural key and the
  recipient's AD stay consistent.)
- **SDK:** `AsyncCryptoAdapter` sharing methods; `VautrMlpClient` HTTP transport
  (`getSharingPublicKey`, `publishSharingPublicKey`, `createShare`,
  `uploadSharePayload`, `listShareInbox`, `revokeShare`); `VautrWebClient`
  `SharingManager` (`ensureSharingKey`, `shareItem`, `getShareInbox`,
  `acceptShare`, `getItemPlaintext`, `revokeShare`); `sharingSecretKey` persisted
  in `IndexedDbStore.StoredState`.
- **Extension UI:** Share button + recipient dialog on each vault item; new
  "Inbox" tab listing received shares with Accept & decrypt / Revoke. The sharing
  secret key is persisted; plaintext is transient (never retained in React state).
- **wasm-pkg** rebuilt (`apps/extension/wasm-pkg`) and the dev shims
  (`apps/web/src/lib/mockWasm.ts`, `apps/extension/src/lib/wasmWeb.ts`) updated
  for type parity.

## Zero-knowledge invariants preserved

- Plaintext item bytes are handed straight from `getItemPlaintext` into
  `share_item` and zeroized by the wasm module — they never enter React state.
- The recipient's sharing secret key lives only in local storage; `accept_share`
  loads it transiently and never retains it.
- The server sees only ciphertext envelopes.
