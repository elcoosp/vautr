# VTR-074 — First-run guided onboarding (mobile)

**Goal.** Extend the VTR-073 web/extension guided onboarding to the **mobile**
app with the *exact same result* (same 5-step contract from
`docs/onboarding/spec.md`), reusing the OnboardJS engine (headless flow state)
and styling it with nativewind so it reads as a native RN screen.

**Approach (chosen: "yes, reuse onboardjs on native").**
Mobile is React Native, so `@onboardjs/react` runs as-is — no fork needed. The
port is:
- `apps/mobile/src/onboarding/steps.tsx` — the 5 `OnboardingStep`s (welcome →
  create-vault → Emergency Kit → add-secret → done), rendered with nativewind
  `View`/`Text`/`TextInput` + the app `Button`/`Card` primitives. CTAs drive real
  surfaces: create-vault → `services.api.createProject`, Emergency Kit →
  `useNavigate({ to: '/mfa' })`, add-secret → `useNavigate({ to: '/secrets' })`.
- `apps/mobile/src/onboarding/OnboardingFlow.tsx` — `OnboardingProvider` mounted
  at the RN app root (`App.tsx`) with **custom persistence** wired to AsyncStorage
  (`customOnDataLoad` / `customOnDataPersist` / `customOnClearPersistedData`) under
  key `vautr_onboarding_v1`. RN has no `localStorage`, so we don't use
  `localStoragePersistence`. Replay = dispatch `vautr:replay-onboarding` +
  `AsyncStorage.removeItem` + `reset()`.
- `apps/mobile/src/routes/_app.settings.tsx` — "Replay onboarding" button.

**Persistence.** AsyncStorage (added `@react-native-async-storage/async-storage`)
via the onboardjs custom hooks — the standard RN pattern, and the "best" choice
for a non-secret first-run flag (not the `expo-secure-store` enclave).
