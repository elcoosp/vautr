# VTR-069 — Server-backed quarantine reaper (SSE event stream)

## Goal
The desktop client runs a local **quarantine reaper** (`vautr_sync::quarantine`)
that emits `ItemRecovered` / `ItemPermanentlyDeleted` events against local
server metadata. Web and extension clients had **no equivalent**: they only
learned about tombstones on the next `sync/pull`. This issue closes that gap
server-side by pushing proactive reaper events over SSE.

## What was built

### Server (`core/vautr-server`)
- **`handlers/events.rs`** (new): `VaultEvent` enum
  (`ItemPermanentlyDeleted(uuid)`, `ItemRecovered(uuid)`), a broadcast channel
  (`AppState.event_tx`), a `GET /events` **SSE** endpoint (auth-gated, axum
  `Sse`), and `spawn_reaper` — a background task that scans tombstoned items
  (`items.deleted_date IS NOT NULL`) every `REAPER_TICK` and re-emits
  `ItemPermanentlyDeleted` (idempotent; clients treat repeats as no-ops).
- **`repository/items.rs`**: `tombstoned_items()` (global scan); `upsert_item_occ`
  now captures prior tombstone state **before** the UPDATE and returns the new
  `UpsertOutcome::Recovered` when a write clears a tombstone.
- **`handlers/items.rs` + `handlers/sync.rs`**: `DELETE /items/{uuid}` publishes
  `ItemPermanentlyDeleted`; `PUT` / `sync/push-batch` that clears a tombstone
  publishes `ItemRecovered`.
- **`handlers/mod.rs`**: `AppState.event_tx` field + `/events` route.
- **`main.rs`**: spawns `spawn_reaper(repo, event_tx)`.

SSE framing follows the real `text/event-stream` contract: each event is
`data: {"type":...,"uuid":...}\n\n`.

### SDK (`packages/vautr-client-sdk`)
- `VautrWebClient.subscribeVaultEvents()` — opens `GET /events` over `fetch` +
  `ReadableStream`, parses SSE frames, maps them to local state:
  - `item_permanently_deleted` → `store.deleteItem(uuid)` + `OverviewDeleted`.
  - `item_recovered` → re-`sync()` to fetch the now-readable payload.
  Auto-reconnects with backoff; returns an unsubscribe fn.
- `ApiClient.getBaseUrl()` / `getToken()` exposed for the SSE fetch.

### Web + Extension
- Both apps call `client.subscribeVaultEvents()` on unlock
  (`apps/web/src/lib/client.ts`, `apps/extension/src/popup/App.tsx`), so tombstone
  / recovery events drive the existing reactive vault store immediately.

### Tests
- Server: 3 new tests in `handlers/events.rs` (SSE data shape, reaper scans only
  tombstoned items, `UpsertOutcome::Recovered` on un-tombstone). Full server
  suite: **63 passed**.
- SDK: 2 new tests in `test/reaper-events.test.ts` (tombstone → delete +
  OverviewDeleted; recovery → re-sync) using an SSE `fetch` shim. Full SDK
  suite: **8 passed**.

## Non-goals / notes
- The local desktop reaper (`vautr_sync::quarantine`) is unchanged; this adds the
  server-side push so thin clients get the same events without a local reaper.
- Recovery requires the client to hold the item (it re-syncs on `item_recovered`);
  the server does not push payloads over SSE (zero-knowledge: payloads stay
  behind `sync/pull`).
