# VTR-073 — First-run guided onboarding (web + extension)

## Context
New users landed in Vautr (web SPA / browser extension popup) with no orientation:
after register/login they dropped straight onto the dashboard/popup with no pointer
to the three first actions that matter — create a vault (project), save the
Emergency Recovery Kit, and add a first secret. A one-time guided setup flow fixes
this.

OnboardJS (`@onboardjs/core` + `@onboardjs/react`) is a **headless multi-step flow
engine**: `OnboardingProvider` + `useOnboarding()` render ONE step at a time via
`renderStep()`, with `localStoragePersistence` (flow shows once), `CUSTOM_COMPONENT`
steps, and an `onFlowComplete` callback. It is **not** an element-spotlight/tour
library — that is explicitly deferred (see scope).

## What was built
- Added `@onboardjs/core@1.0.0-rc.4` + `@onboardjs/react@1.0.0-rc.5` to
  `apps/web` and `apps/extension` (pinned RCs; core max published is rc.4, react
  rc.5 peer-requires core >=rc.1 so rc.4 satisfies it).
- Web: `apps/web/src/onboarding/steps.tsx` (welcome → create-vault →
  emergency-kit → add-secret → done) + `OnboardingFlow.tsx`
  (`OnboardingProvider` with `localStoragePersistence={{ key: 'vautr_onboarding_v1' }}`
  rendering a centered overlay). Mounted in `apps/web/src/main.tsx` around
  `RouterProvider`. `Settings` page gained a "Replay onboarding" card.
- Extension: mirror under `apps/extension/src/onboarding/` (same steps; tab-switch
  via `usePopupStore.setActiveTab` instead of route nav). Mounted in
  `apps/extension/src/popup/main.tsx`; "Replay onboarding" button added to the
  popup footer.
- Steps drive real surfaces: `mlp.createProject` (web + ext), `navigate`/`setActiveTab`
  to projects/settings/secrets. No stubs.

## Zero-knowledge note
Onboarding only navigates / calls existing client APIs (`createProject`) — no
secret plaintext is rendered by the flow itself. Emergency-Kit step points at the
existing recovery flow (already ZK).

## Out of scope (deferred)
- **Feature/product tour** (anchored tooltips highlighting UI elements). OnboardJS
  has no element-anchor API; a later issue will add a custom `CUSTOM_COMPONENT`
  spotlight overlay or a dedicated tour lib. Tracked as follow-up, not blocking.
