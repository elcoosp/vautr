## What to build

SQLite schema (via `sqlx` migration) for `items` table: `uuid TEXT PRIMARY KEY`, `user_id TEXT`, `version INTEGER`, `enc_key_gen INTEGER`, `deleted_date INTEGER`, `payload BLOB`, `updated_at INTEGER`. Plus a function `update_item_atomic(uuid, user_id, target_version, new_payload) -> Result<u64, DbError>` that performs `UPDATE ... WHERE version = target_version` and returns new version.

## TDD Instructions

1. **Write an integration test** that creates an item (version 1), then calls `update_item_atomic` with target_version=1; asserts rows_affected == 1 and version becomes 2.
2. **Write a test** that attempts update with wrong target_version; asserts rows_affected == 0 and returns `DbError::OptimisticLockFailure`.
3. **Write a test** that updates an item with a newer `enc_key_gen`; asserts success only if `enc_key_gen >= server_min_enc_key_gen` (initially 1).
4. **Write a test** that tries to update an item belonging to a different `user_id`; asserts no rows updated.

Implementation: use `sqlx::query` with `RETURNING version`. The `user_id` is passed from auth middleware (mocked in test).

## Acceptance criteria

- [ ] Migration creates `items` table with correct indexes.
- [ ] Concurrent updates using the same target_version result in only one success (test with `tokio::spawn`).
- [ ] The function returns the new version or error.
