## What to build

Accessibility improvements to the React web application:
- Semantic HTML (headings, landmarks, aria labels).
- Keyboard navigation (Tab, Enter, Escape) for all interactive elements (list, detail view, modals).
- Colour contrast meets 4.5:1 for normal text.
- Focus indicators visible.
- Screen reader announcements for sync status, conflict resolution, and copy actions.

## TDD Instructions

1. **Write an automated a11y test** using `axe-core` and Playwright – run against all routes and assert zero violations of WCAG 2.1 AA.
2. **Write a manual test script** that navigates the vault using only a keyboard – assert every action (add, edit, delete, copy, sync) can be completed without a mouse.
3. **Write a test** using a screen reader simulator (e.g., `@guidepup/guidepup`) that reads the conflict resolution modal and verifies the options are announced.
4. **Write a test** that ensures the colour contrast of the “Read‑Only Gate” banner passes the 4.5:1 ratio.
5. **Write a test** for focus management: after deleting an item, focus moves to the next item in the list (not lost).

Implementation: use `tailwindcss` for theming with accessible colours. Add `role` and `aria-*` attributes to dynamic components.

## Acceptance criteria

- [ ] `axe-core` reports zero violations in CI.
- [ ] All interactive elements are reachable and operable with keyboard.
- [ ] Screen reader users can understand all state changes (sync, conflict, rotation).
