## What to build

During vault creation:
- Real‑time password strength meter (zxcvbn or similar) – estimates crack time.
- Background calibration of Argon2id: runs on the device to find `m_cost` and `t_cost` such that derivation takes ~300 ms. Parameters are saved and reused for future unlocks.
- The calibration runs only once per device (cached).

## TDD Instructions

1. **Write a test** that runs the calibration function on a reference machine and asserts the resulting parameters derive a key within 250–350 ms (measured).
2. **Write a test** that the strength meter updates as the user types – shows “Weak”, “Fair”, “Strong”, “Very Strong” based on zxcvbn score.
3. **Write a test** that the strength meter does not log the password (no console output).
4. **Write a test** that the calibration results are stored in local storage and reused on subsequent launches (skip re‑calibration).
5. **Write a test** that if the device hardware changes dramatically (e.g., after an upgrade), the calibration can be re‑run manually in settings.

Implementation: use `zxcvbn` crate for strength, `argon2` crate with a calibration loop that doubles `m_cost` until target time is reached.

## Acceptance criteria

- [ ] Password strength is shown without transmitting the password to any server.
- [ ] Unlock time is consistent across devices (~300ms).
- [ ] The user is warned about weak passwords.
