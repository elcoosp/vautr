## What to build

Inside `vautr-app-state`, implement:
- `reveal_secret(uuid: Uuid) -> Result<SecretHandle, CoreError>`: decrypts secret, stores in an internal `DashMap<SecretHandle, ActiveSecret>`, returns u64 handle.
- `perform_action(action: CoreAction) -> Result<(), CoreError>`: for `CoreAction::CopyToClipboard { handle }`, reads secret from DashMap, calls platform adapter (trait).
- `release_secret(handle: SecretHandle) -> Result<(), CoreError>`: removes entry and zeroizes.

Handle state includes `InUse` or `Idle`, `last_accessed`, and the secret.

## TDD Instructions

1. **Write a test** that calls `reveal_secret`, gets a handle, then `perform_action` with `CopyToClipboard` – assert the platform adapter receives the correct secret.
2. **Write a test** that calls `release_secret` and then tries to `perform_action` with the same handle – must return `CoreError::HandleInvalid`.
3. **Write a test** that reveals a secret, then calls `release_secret` twice – second call returns `HandleInvalid`.
4. **Write a test** that ensures `reveal_secret` sets state to `InUse`, and `release_secret` transitions to `Idle` before zeroizing.
5. **Write a stress test** that reveals 1000 secrets concurrently, uses them, and releases them – no panics, no handle collisions.

Implementation: use `Arc<DashMap<u64, ActiveSecret>>` with an atomic counter for handle generation.

## Acceptance criteria

- [ ] Handles are not reused immediately after release (avoid ABA).
- [ ] `perform_action` does not clone the secret into the platform adapter’s heap unless necessary.
- [ ] The platform adapter trait is generic over the OS clipboard.
