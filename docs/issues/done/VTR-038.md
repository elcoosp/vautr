## What to build

Two E2E test suites:
- **Web**: Playwright script that runs against a local server and the WASM client.
- **Mobile**: Maestro (or Detox) script that runs on an emulator/simulator.

The tests cover:
- User registration, vault creation, adding an item.
- Offline edit → online sync conflict (412 modal).
- Key rotation → read‑only gate → re‑authentication.
- Copy password via opaque handle (no JS string leak).

## TDD Instructions

1. **Write a Playwright test** that registers a new user, adds a password, then on a second browser (or context), edits the same password, triggers a conflict, and resolves by “Keep Server Version” – assert the first browser shows the updated value.
2. **Write a Maestro test** that on an Android emulator, unlocks with biometrics (mocked), copies a password, and uses the system clipboard to paste into a test web view – assert the secret matches.
3. **Write a test** that rotates the SVK (via settings), then on a lagged device (simulated by using a different client build with an older sync cursor) attempts to edit – read‑only gate appears, re‑authentication succeeds, and edits are enabled.
4. **Write a test** that imports a CSV with 100 items, then searches for a keyword and verifies results appear.
5. **Write a test** that attaches a file (1 MB) to an item, syncs, and then downloads it on another device – assert the file content matches.

Implementation: use `playwright-chrome` for web, `maestro` YAML flows for mobile. Run against a local test server with a clean SQLite database per test.

## Acceptance criteria

- [ ] All critical user journeys are covered.
- [ ] Tests run nightly and on release branches.
- [ ] No flaky tests (retry logic with at most 1 retry).
