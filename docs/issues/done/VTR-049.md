## What to build

For the GPUI desktop app, implement an auto‑updater that:
- Checks a public endpoint (e.g., `https://updates.vautr.com/desktop/latest`) for the latest version.
- Downloads the new installer package (`.dmg`, `.exe`, `.deb`) over HTTPS.
- Verifies the package signature (using ed25519 or similar) against a public key embedded in the app.
- Prompts the user to install (or installs silently with user consent).
- Rolls back on signature failure.

## TDD Instructions

1. **Write a test** that mocks the update server returning a new version; the updater downloads a test package, verifies its signature, and prompts the user – assert the update is accepted.
2. **Write a test** where the signature is invalid (tampered package) – the updater rejects and logs an error.
3. **Write a test** that the update check respects user preference (auto‑update on/off).
4. **Write a test** that the updater does not block the main UI – it runs in a background thread.
5. **Write a test** that after an update is installed, the app restarts and the new version is reported.

Implementation: use `reqwest` for download, `ed25519` for signature verification, and platform‑specific installer invocation (e.g., `open` on macOS, `msiexec` on Windows). For GPUI, use a separate process to replace the binary.

## Acceptance criteria

- [ ] Updates are delivered over HTTPS.
- [ ] The public key is hardcoded and cannot be replaced by a MITM.
- [ ] The user is notified and can postpone.
