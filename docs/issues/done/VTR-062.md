## What was found

Most of the ZK reveal architecture was **already built** (earlier work):
- `core/vautr-wasm/src/client.rs` — `WebClient` decrypts item payloads in WASM
  behind an opaque `u32` handle (`reveal_secret`), hands plaintext only to a
  JS-registered clipboard/autofill handler via `perform_action`, and
  `release_secret` zeroizes it. A `setInterval` Safety Reaper zeroizes idle
  handles after 60s (REQ-SECRET-05).
- `packages/vautr-client-sdk/src/worker.ts` — runs `WebClient` inside a Web
  Worker; plaintext never crosses to the main thread except via the clipboard
  event.
- `apps/web/src/components/ItemDetail.tsx` + `apps/web/src/lib/client.ts` —
  `reveal` / `performAction` / `release` handle lifecycle; `ItemDetail` keeps the
  handle in a `useRef` and releases on unmount (no plaintext in React state).

The remaining **acceptance-criterion gap** was that two web views still used the
old HTTP reveal (`mlp.revealSecret` → server-decrypted `value_ciphertext`) and
held the plaintext in React state:
- `apps/web/src/routes/_authed/secrets.tsx` (All-secrets table)
- `apps/web/src/routes/_authed/projects/$uuid.tsx` (project secrets table)

This violated criterion 3 (no plaintext in React state).

## What was changed (VTR-062 final gap)

Converted both views to the handle-based `reveal` / `performAction` /
`release` lifecycle (mirroring `ItemDetail`):
- Removed the `mlp.revealSecret` HTTP call and the `revealed` plaintext-in-state
  map from both files.
- `onReveal(uuid)` now: `reveal(uuid)` → opaque handle, `performAction({type:
  "CopyToClipboard", handle})` (copies via the wasm clipboard handler), then
  `release(handle)` in a `finally`. Plaintext never enters React state or the
  DOM; only a transient "Copied" flag is tracked.
- Removed the inline plaintext render blocks and the now-unused `b64decode`
  helpers; button toggles Reveal/Copied.

## Not run

- No browser runtime click-through of the copy-to-clipboard reveal (needs a
  display + live server); the path is type-checked, builds, and the wasm
  `WebClient` handle/reaper logic is covered by `vautr-wasm` unit/live-server
  tests.
- **Extension** (`apps/extension`) still holds plaintext in React state in
  `VaultTab.tsx` / `SecretsTab.tsx` — that is VTR-064's scope, not this issue.

## Acceptance criteria

- [x] Decrypt happens in WASM, not JS (wasm `WebClient.reveal_secret`).
- [x] Plaintext is zeroed after reveal interaction (`release_secret` + reaper).
- [x] No plaintext in React/extension state during normal reveal (web views
      converted; extension deferred to VTR-064).
