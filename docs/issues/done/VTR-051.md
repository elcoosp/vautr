## What to build

Server endpoints for streaming file upload/download using presigned URLs (RustFS):
- `POST /files/{file_uuid}/upload/initiate` – creates a multipart upload session, returns `upload_id` and an array of presigned URLs (one per 1 MiB chunk).
- `POST /files/{file_uuid}/upload/complete` – assembles chunks, marks file as available.
- `GET /files/{file_uuid}/download` – returns presigned GET URLs for each chunk.
- `DELETE /files/{file_uuid}` – deletes all chunks.

Client `FileTransferWorker` uses these endpoints to upload encrypted chunks concurrently (up to 3 at a time) and resume after interruption.

## TDD Instructions

1. **Write a test** that initiates an upload for a 5 MiB file, uploads all chunks via presigned URLs, then completes – asserts the file can be downloaded and decrypted to the original.
2. **Write a test** that simulates a network failure after the 3rd chunk; the client resumes by calling `GET /files/{uuid}/upload/status` and uploads only the missing chunks.
3. **Write a test** that completes a file, then attempts to download it on a different device – succeeds.
4. **Write a test** that deletes a file (via `DELETE /files/{uuid}`) and verifies all chunks are removed from RustFS (using a mock or real cleanup check).
5. **Write a performance test** that uploads a 100 MiB file – measures throughput and asserts it does not exceed memory limits (peak RAM < 50 MiB).

Implementation: on the server, use RustFS’s multipart API. Presigned URLs expire after 15 minutes. The client must retry with a new `initiate` if they expire.

## Acceptance criteria

- [ ] Uploads and downloads are resumable.
- [ ] The server never sees the plaintext (only encrypted chunks).
- [ ] Quotas are enforced (free tier limit).
