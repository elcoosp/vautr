## What to build

Optional second factor using WebAuthn (hardware security key or platform authenticator):
- During MP unlock, after MP verification, the client requests a WebAuthn assertion.
- Server stores registered credential IDs and public keys.
- Client uses the Web Authentication API (navigator.credentials.get) to obtain an assertion.
- Server verifies the assertion signature and counter.

This feature is **behind a feature flag** and disabled by default.

## TDD Instructions

1. **Write a test** (using a virtual authenticator via `webdriver`) that registers a hardware key, then performs MP unlock + WebAuthn assertion – succeeds.
2. **Write a test** where the WebAuthn assertion fails (wrong key or cancelled) – login fails with `AuthError::SecondFactorRequired`.
3. **Write a test** that the user can disable second factor (after MP verification) – the server removes the credential.
4. **Write a test** that the server supports multiple registered keys per user (e.g., backup key).
5. **Write a test** that the WebAuthn flow works offline (using cached credential ID – but assertion still requires online? Actually WebAuthn can work offline but server needs to verify signature, so offline not supported. Mark as online‑only.)

Implementation: use `webauthn-rs` crate on server, and the browser’s WebAuthn API on web client. For desktop, use a native WebAuthn bridge (e.g., `webauthn-rs` with `libu2f`).

## Acceptance criteria

- [ ] Works on Chrome, Edge, Safari, Firefox.
- [ ] Falls back gracefully if no security key is available.
- [ ] The feature is optional and clearly marked as “experimental” in v1.0.
