## What to build

`packages/ui-logic` with:
- Zustand store that holds a map of `DecryptedOverview` (keyed by UUID).
- An event bus that subscribes to `VaultStateUpdate` events from a mock client.
- A draft slice that stores pending edits keyed by `TaskReceipt` (as string), with methods to set, get, and delete drafts.

All stores must never persist to disk (no `localStorage`).

## TDD Instructions

1. **Write a test** (Vitest) that uses the Zustand store to upsert an overview, then retrieves it – must match.
2. **Write a test** that calls the `deleteOverview` action and verifies the item is removed.
3. **Write a test** that simulates a `VaultStateUpdate::MutationFailed` event, extracts the draft by receipt, and asserts the draft is returned.
4. **Write a test** that after calling `clearDraft(receipt)`, the draft is undefined.

Implementation: create a vanilla Zustand store with slices. The event bus can be a simple `EventEmitter` that forwards mock updates.

## Acceptance criteria

- [ ] `pnpm test` in `ui-logic` passes.
- [ ] Store does not use any persistence middleware.
- [ ] Drafts are stored in memory only.
