## What to build

Axum handler for `POST /sync/push-batch` that:
- Accepts up to 100 items.
- For each item, checks `enc_key_gen >= min_enc_key_gen` (global for user).
- Checks OCC via atomic update (`WHERE version = target_version`).
- Commits **all** successful updates in a single SQLite transaction.
- Returns a list of results (success or conflict) per item.
- Rejects the entire batch if any item has `enc_key_gen` too old (422).

## TDD Instructions

1. **Write a test** (using `sqlx` test transaction) that sends a batch of 3 valid items; asserts all succeed and versions increment.
2. **Write a test** where one item has a version conflict (412); assert that the batch returns a conflict for that item but the other items still succeed (atomic commit).
3. **Write a test** where one item has `enc_key_gen = 0` while `min_enc_key_gen = 2`; assert entire batch is rejected with 422 and no changes persisted.
4. **Write a test** that sends 101 items – must return 400 `payload_limit_exceeded`.
5. **Write a test** that simulates concurrent batch pushes on overlapping items; using `tokio::spawn` and `assert` that only one succeeds for each conflicting item.

Implementation: use `sqlx::Transaction` and loop over items; if any epoch check fails, rollback and return 422.

## Acceptance criteria

- [ ] All tests pass.
- [ ] The endpoint returns a multi‑status JSON with per‑item results.
- [ ] The update uses `RETURNING version` to get new version.
