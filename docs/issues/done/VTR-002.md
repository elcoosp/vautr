## What to build

`vautr-domain` crate containing all shared structs, enums, and type aliases from `data.md`. No logic, no I/O, no FFI – only data definitions with `serde` derives. Use `Zeroizing` for secret fields.

## TDD Instructions

Because this crate has no logic, the “test” is compile‑time validation:

1. **Write a doctest** that constructs a `DecryptedOverview` and asserts its fields are accessible.
2. **Write a compile‑fail test** (using `trybuild`) that attempts to derive `Debug` on `DecryptedSecret` – must fail compilation.
3. **Write a test** that creates a `DomainModel` and serializes it to JSON, then back, using `serde_json` – must round‑trip exactly.

Implementation must provide all types from the specification, with `Zeroizing` wrapping any password, TOTP secret, or note.

## Acceptance criteria

- [ ] `cargo test -p vautr-domain` passes.
- [ ] `Debug` is not implemented on secret‑holding types.
- [ ] All types are `Serialize + Deserialize`.
