## What to build

A GitHub Actions release workflow triggered by `v*` tags:
- Builds server Docker images for `linux/amd64` and `linux/arm64` (using `docker buildx`).
- Builds desktop binaries for macOS (Intel + Apple Silicon), Windows, and Linux (`.deb`, `.AppImage`).
- Builds web app (static files) and deploys to Vercel/Cloudflare.
- Builds extension (zip) and uploads to Chrome Web Store and Firefox Add‑ons (using their APIs).
- Signs macOS binary (codesign) and Windows binary (signtool).
- Creates a GitHub release with all artifacts attached.

## TDD Instructions

Verification is manual/automated:

1. **Write a CI check** that after a tag push, the release workflow runs and produces artifacts – assert that the Docker image for `linux/arm64` exists in ECR/GHCR.
2. **Write a test** that downloads the macOS `.app` from the release, runs `codesign -v`, and verifies it is signed and notarised.
3. **Write a test** that starts the server from the Docker image and runs the k6 load test against it – must pass.
4. **Write a test** that installs the extension from the generated `.zip` into a fresh Chrome profile and verifies it loads without errors.
5. **Write a test** that the web app’s WASM bundle is optimized (`wasm-opt -Oz`) and its size is < 5 MB.

Implementation: use `docker/build-push-action`, `tauri` bundler (or `cargo-bundle`), and GitHub Actions artifacts.

## Acceptance criteria

- [ ] Every release tag creates a GitHub release with all binaries.
- [ ] The server Docker image is multi‑arch and runs on Raspberry Pi 4.
- [ ] The extension is published to the stores automatically (optional – manual approval required).
