## What to build

Browser extension service worker (Manifest V3) that:
- On autofill trigger, reads SVK from `chrome.storage.session` (cleared on browser close).
- Fetches the encrypted item from `chrome.storage.local` (cached).
- Uses a lightweight WASM build of `vautr-crypto` (nodejs target) to decrypt the secret.
- Injects the password into the webpage.
- Does **not** hold any SQLite connection or DashMap (stateless).

Popup uses the full WASM client (as web app) for sync and unlock.

## TDD Instructions

1. **Write a test** using Playwright with Chrome extension API that simulates:
   - Unlock in popup → SVK cached in `session`.
   - Close popup (simulate SW idle).
   - Trigger autofill on a login page → assert field is filled within 500ms.
2. **Write a test** that after browser restart, `session` is empty – autofill fails and triggers user to unlock again.
3. **Write a test** that ensures the SW does not load SQLite or DashMap (check bundle size and symbols).
4. **Write a test** that the SW terminates after 30 seconds idle and autofill still works (reactivates).
5. **Write a test** where the server returns a 401 (expired token) – autofill shows error and prompts re‑authentication.

Implementation: separate WASM build `--target nodejs` for crypto only. Use `chrome.storage.session.setAccessLevel` to allow SW access.

## Acceptance criteria

- [ ] No persistent storage of SVK (only `session`).
- [ ] SW bundle size < 1 MB (only crypto, no DB).
- [ ] Autofill works on Chrome, Edge, Firefox (MV3).
