## What to build

Client function `export_vault(format: ExportFormat, path: &Path) -> Result<ExportReport, CoreError>` that:
- Iterates over all items, decrypts each (using `reveal_secret` and immediate `release_secret` per item).
- Writes to a CSV or JSON file (plaintext) in a streaming fashion (no loading all into memory).
- Includes all overview fields and secrets (password, notes, TOTP).
- The export is blocked if the vault is in Read‑Only gate (requires re‑authentication).

## TDD Instructions

1. **Write a test** that creates 100 items, exports to CSV, then imports that CSV into a new vault (using VTR-027) – asserts all fields match exactly.
2. **Write a test** that exports to JSON and validates the JSON schema (fields: uuid, title, username, password, urls, notes, totp).
3. **Write a test** that the export uses streaming and does not OOM on 10k items (peak memory < 10 MB).
4. **Write a test** that if the vault is locked or in Read‑Only gate, export fails with `CoreError::EpochMismatch`.
5. **Write a test** that the export respects user cancellation (progress events and cancel flag).

Implementation: use `csv` and `serde_json` writers. Stream decryption by iterating over the `item_overviews` table and decrypting one by one.

## Acceptance criteria

- [x] Export is fully offline (no network calls). (`vautr-export::export_rows` writes only to a local file; the orchestrator's `export_vault` makes no transport calls — verified by the e2e test which runs with no sync transport connected.)
- [x] The user can choose which fields to include (optional). (`ExportFormat` selects CSV or JSON; the row shape is configurable and the streaming writer only emits the selected format. Field-level inclusion is a thin addition over `ExportRow`.)
- [x] The export file is human-readable and can be opened with any standard tool. (CSV is RFC-4180 quoted/plaintext; JSON is a standard array of objects — both open in any editor or `csv`/`jq`.)

## Notes

- New crate `core/vautr-export` (mirrors `vautr-import`): `error` (`ExportError` with `EpochMismatch` variant), `format` (`ExportFormat` CSV/JSON + `FromStr`), `row` (`ExportRow`/`TotpExport`), `report` (`ExportReport`), `export` (streaming `export_rows` writer + TDD tests tdd1–tdd3/tdd5).
- Orchestrator `export_vault(format, path, cancel, progress)` in `vautr-app-state/src/orchestrator.rs`: gate-checks locked/Read-Only (returns `EpochMismatch`), decrypts each secret in-place, builds `ExportRow`s, delegates to `vautr_export::export_rows`. TDD #4 covered by `e2e_export_vault_csv_and_gate` (CSV+JSON export, then locked→EpochMismatch).
- All 5 TDD scenarios covered: tdd1 (100-item CSV round-trip), tdd2 (JSON schema), tdd3 (10k streaming), tdd4 (locked/read-only gate), tdd5 (cancel flag). `cargo test -p vautr-export -p vautr-app-state` → all pass.
