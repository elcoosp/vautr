## What to build

Integrate the validated reaper (VTR-022) with the sync engine and UI:
- When the reaper successfully deletes a toxic item (tombstone), emit `VaultStateUpdate::ItemPermanentlyDeleted(uuid)`.
- When the reaper drops a quarantine entry because the item became valid (lagged device re‑authed), emit `VaultStateUpdate::ItemRecovered(uuid)`.
- UI shows a toast: “A previously unreadable item has been recovered” and re‑syncs automatically.

## TDD Instructions

1. **Write a test** that sets up a quarantine entry for a toxic item, then runs the reaper after the item becomes valid (simulate by updating server metadata). Assert the UI receives `ItemRecovered` and the item reappears in the list.
2. **Write a test** that the reaper, after tombstoning, emits `ItemPermanentlyDeleted` – the UI removes the item if it was still shown as toxic.
3. **Write a test** that multiple items are recovered in one reaper run – each emits its own event (no batching loss).
4. **Write a test** that the reaper does **not** emit events for items that were already removed from the UI (e.g., user deleted locally).
5. **Write a test** that the recovery trigger causes an immediate sync pull (to fetch the now‑valid payload).

Implementation: add a channel from `vautr-sync` to the event bus. The reaper runs in a background task and sends events.

## Acceptance criteria

- [ ] Users are notified when a previously toxic item becomes readable.
- [ ] The UI does not show stale toxic indicators after recovery.
- [ ] No duplicate events.
