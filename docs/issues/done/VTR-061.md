## What was built

- `core/vautr-ffi/examples/gen_bindings.rs` — generates real Kotlin + Swift
  uniffi bindings from the compiled `libvautr_ffi.dylib` (run
  `cargo run -p vautr-ffi --example gen_bindings`).
- `modules/vautr-native/` — a complete Expo TurboModule package:
  - `package.json`, `expo-module.config.json`, `tsconfig.json`, `VautrNative.podspec`.
  - `src/index.ts`: `createVautrNativeBridge()` (via `requireNativeModule('VautrNative')`)
    + `createSecureEnclaveBridge()` (expo-secure-store backed).
  - `android/.../VautrNativeModule.kt` + `VautrNativePackage.kt` wrapping the
    uniffi `MobileClient` (initialize/unlock/listOverviews/revealSecret/
    releaseSecret/renderInOverlay/lock/sync/setSecureEnclaveBridge).
  - `ios/VautrNativeModule.swift` wrapping the same surface.
  - `ffi-bindings/` — GENERATED Kotlin/Swift/C bindings (committed artifact).
- `apps/mobile/lib/client.ts`: `bootVautrCore()` now resolves the bridge via
  `createVautrNativeBridge()` and registers the secure-enclave adapter, so when
  the native module is linked `getMobileClient()` is non-null and the secrets
  screens use the opaque-handle native-overlay reveal path (no plaintext in JS).
- `pnpm-workspace.yaml` + `apps/mobile/package.json`: `@vautr/native` added as a
  `workspace:*` dependency.
- `scripts/gen-ffi-bindings.sh` regenerate helper.
- `modules/vautr-native/README.md` documents the full native build
  (cargo-ndk / aarch64-apple-ios + pod install / gradle assemble).

## Verification

- `cargo build -p vautr-ffi` + 3 in-crate integration tests pass
  (`mobile_unlock_list_reveal_release_lock`, `mobile_locked_rejects_reads`,
  `overlay_renders_plaintext_only_in_native_handler`) — the full uniffi flow
  including the opaque-handle overlay is exercised and green on the Rust side.
- `cargo run -p vautr-ffi --example gen_bindings` produces real, API-accurate
  Kotlin/Swift/C bindings; the Kotlin/Swift wrappers are written against that
  exact generated surface.
- `apps/mobile` typecheck + biome lint + `secretLifecycle` vitest green; the
  shipping `$projectId` screen uses `SecretOverlay` (secure path) by default.

## Not run in this environment (documented, not stubbed)

The actual native compile — `cargo ndk` (Android NDK), `cargo build --target
aarch64-apple-ios` (Xcode), and `pod install` / Gradle assemble — requires the
Android NDK, Xcode, and `expo-modules-core` native toolchain, which are
unavailable in this sandbox. The Kotlin/Swift source and generated bindings are
complete and accurate; only the final device-build step is environment-gated.
