## What to build

In `vautr-crypto` (or a new `vautr-files` crate):
- `encrypt_file_stream(input: impl AsyncRead, output: impl AsyncWrite, key: &[u8; 32]) -> Result<FileManifest, CryptoError>` that reads the input in 1 MiB chunks, encrypts each chunk with XChaCha20-Poly1305 using a deterministic nonce derived from `file_uuid || chunk_index`, and writes ciphertext chunks to an output stream.
- `decrypt_file_stream(input: impl AsyncRead, output: impl AsyncWrite, key: &[u8; 32], manifest: &FileManifest) -> Result<(), CryptoError>` that reads chunk by chunk, decrypts, and writes plaintext.

Nonce = `SHA256(file_uuid_bytes || chunk_index.to_be_bytes())[..24]`.

## TDD Instructions

1. **Write a test** that encrypts a 3.5 MiB random file, then decrypts it; assert the output matches the original.
2. **Write a test** that encrypts a 1-byte file – chunking works with the last partial chunk.
3. **Write a test** that corrupts a single chunk in the encrypted stream and attempts decryption – must fail with `TagMismatch` at that chunk.
4. **Write a test** that resumes encryption after a crash: the chunk index is derived from `FileManifest.total_chunks`, so restarting from the same offset works.
5. **Write a property‑based test** that validates the deterministic nonce never repeats for the same `file_uuid` and different chunk indices.

Implementation: use `futures::AsyncReadExt` and `futures::AsyncWriteExt`. The `FileManifest` includes `total_size`, `chunk_size`, `total_chunks`, `enc_key_gen`.

## Acceptance criteria

- [ ] Memory usage is bounded to ~2 MiB (plaintext + ciphertext buffer).
- [ ] Nonce reuse is impossible for different chunks of the same file.
- [ ] The manifest can be serialized to JSON and stored in the item’s payload.
