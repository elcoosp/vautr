# VTR-084 — Low-contrast links/labels (`text-accent` rendered as dark slate)

**Status:** done (fixed in d10728b: `--color-accent: var(--primary)` on both `@theme` blocks in apps/web/src/index.css; emerald #42b59a restored).
**Date:** 2026-08-15
**Clients:** web, mobile, extension (systemic token bug)

## Symptom
User: "the register an account link is not visible contrast". The "Register an
account" link on the login page (and ~50 other `text-accent` usages across web /
mobile / extension) rendered near-invisible: dark-slate text on a dark card.

## Root cause
`apps/web/src/index.css` defined `--color-accent` **twice**:
- `@theme { --color-accent: var(--primary); }` (emerald)  — correct intent
- `@theme inline { --color-accent: var(--accent); }` (slate `#1e252e`) — won,
  because it appeared later in the cascade.

So every `text-accent` (links, button labels, icons, focus rings) resolved to the
*slate surface* color instead of the emerald brand color. The `--accent` token is
a surface/hover color, never meant for text.

## Fix
- `apps/web/src/index.css`: `--color-accent: var(--primary)` (emerald `#42b59a`),
  `--color-accent-foreground` / `--color-accent-ink` → `var(--primary-foreground)`
  (light text). Same value on both `@theme` and `@theme inline` blocks (removed the
  conflicting slate override). Mobile/extension inherit the same `@vautr/design-tokens`
  `--accent` token; their `text-accent` usages now also resolve correctly via the
  shared theme.
