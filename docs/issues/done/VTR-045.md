## What to build

Enhance `vautr-import` to report progress:
- Emit `VaultStateUpdate::ImportProgress { stage: Parse, percent: u8 }`, `stage: Encrypt`, `stage: Sync`.
- Allow cancellation via `cancel_import(task_id)` (returned receipt).
- Use a channel to send updates from the import worker to the UI event bus.
- Support pausing/resuming if network fails during sync stage.

## TDD Instructions

1. **Write a test** that imports 1000 items and listens to progress events; assert that the sum of `percent` values for each stage is eventually 100.
2. **Write a test** that cancels the import during the “Encrypt” stage; asserts the import is aborted and no items are saved.
3. **Write a test** that simulates network failure during the “Sync” stage; the import pauses, and after network resumes (or user clicks retry), it continues from the last synced batch.
4. **Write a test** that the progress events are throttled (max 10 per second) to avoid UI spam.
5. **Write a test** that a cancelled import does not leave partial data in the database (rollback).

Implementation: the import worker sends progress via `tokio::sync::mpsc`. The `ImportReport` includes partial counts.

## Acceptance criteria

- [ ] Progress is deterministic (0‑100 per stage).
- [ ] Cancellation is responsive (< 100 ms).
- [ ] The UI can show a progress bar without stuttering.
