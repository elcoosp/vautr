## What to build

A native component (Android View / SwiftUI View) that:
- Receives a `SecretHandle` (as UInt64) from React Native (via Turbo Module).
- Calls `core.read_secret(handle)` (via UniFFI) – but note: mobile builds have `read_secret` gated OFF! Wait – careful: The spec says mobile **cannot** call `read_secret`; instead it uses `perform_action`. However, for **rendering** the secret on screen (when user taps “Reveal”), the native overlay needs to obtain the plaintext. According to ADR‑003, mobile uses **opaque handle** and the native overlay must call `read_secret` **only in native code** (not JS). That is allowed because the handle is resolved in native, not JS.

Thus: Expose `read_secret` via UniFFI but **only to native code** (not to JS). The Turbo Module does not expose it to JS. The native overlay component will be implemented in Kotlin/Swift and directly call the FFI.

## TDD Instructions

1. **Write a Kotlin test** that creates a `SecretHandle` (by calling `reveal_secret` from native code), then uses a custom `NativeSecretView` that calls `read_secret` and renders the text in a `TextView`. Assert the displayed text matches the expected password.
2. **Write a Swift test** that does the same with `UILabel`.
3. **Write a test** that when the native overlay is unmounted (e.g., navigation pop), it calls `release_secret` automatically (via `onDetachedFromWindow` / `deinit`).
4. **Write a test** that the JS side never receives the plaintext string – only the handle (as string) is passed via the Turbo Module, and the native component renders it.
5. **Write an E2E test** (Maestro) that taps “Reveal” on a password field, verifies the text is visible, then navigates away and verifies the secret is cleared (no leftover in memory).

Implementation: Turbo Module exports `revealSecret(uuid) -> Promise<string>` that returns the handle as string; the native component uses that handle. The actual secret retrieval happens entirely in native.

## Acceptance criteria

- [ ] `read_secret` is compiled into mobile binaries (since it’s called from native) but **not** exposed to JS (symbol check passes).
- [ ] The native overlay component is reusable and secure.
- [ ] Memory is zeroized on unmount.
