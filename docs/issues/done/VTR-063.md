## What was found

Most of VTR-063 was already built: the `Section` enum, the web-style sidebar
(10 nav items incl. Machine accounts / Tokens / Import-export), and the
`render_machine_accounts` / `render_tokens` / `render_import_export` sections
were all present and wired through `activate_section` + `render_app`. Import and
export already call the real `api.backup_export` / `api.backup_status` core
methods (verified, not stubs).

The only unmet acceptance criterion was **sharing an item + key rotation from the
UI** — there was no share or rotate-key surface at all.

## What was added (VTR-063 final gap)

- `apps/desktop/src/desktop_view.rs`:
  - State: `pending_share: Option<Uuid>`, `share_recipient_input`,
    `share_text`, `key_gen: u64` (seeded from `session.min_enc_key_gen` at unlock).
  - `request_share` (opens modal), `do_share` (reveals locally via
    `client.reveal_secret`/`read_secret`, then `client.share_item(recipient,
    uuid, plaintext.as_bytes())`), `do_rotate_key` (`client.rotate_key(key_gen+1)`).
  - "Share" button on the vault item row; `render_share_modal` (recipient UUID
    input + confirm/cancel), mounted in `render_app`.
  - "Vault key rotation" card in `render_mfa` showing current generation + a
    "Rotate key" button.

(`share_item`, `rotate_key`) are exercised by `vautr-app-state` unit tests.
