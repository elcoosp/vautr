## What to build

SQLite schema (via SeaORM migration) for client:
- `item_overviews` table (hot) with fields `uuid`, `version`, `enc_key_gen`, `deleted_date`, `overview_title`, `overview_subtitle`, `overview_icon_key`, `overview_urls` (JSON), `created_at`, `updated_at`.
- `item_payloads` table (cold) with `uuid` primary key and `payload` BLOB.
- FTS5 virtual table `items_fts` indexing `title`, `subtitle`, `urls` from `item_overviews`.
- Triggers to keep FTS in sync.

## TDD Instructions

1. **Write an integration test** that inserts an overview and payload, then queries `item_overviews` and joins `item_payloads` – must return both.
2. **Write a test** that updates an overview and checks that the FTS5 index reflects the change (use `MATCH` query).
3. **Write a test** that deletes an overview and verifies the corresponding payload is also deleted (cascade by application logic, not FK).
4. **Write a test** that searches with a keyword and returns correct UUIDs.

Implementation: use SeaORM `MigrationTrait`. The FTS5 triggers must be written as raw SQL.

## Acceptance criteria

- [ ] Migration runs without errors.
- [ ] FTS5 search returns results within 100ms for 10k items (benchmark test).
- [ ] The `overview_urls` column stores JSON array as text.
