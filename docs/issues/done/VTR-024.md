## What to build

A background task spawned when `VautrClient` is created that:
- Every 10 seconds, scans the DashMap of `ActiveSecret`s.
- For entries with `state == Idle` and `last_accessed.elapsed() > 60 seconds`, zeroizes the secret and removes the entry.
- Emits a `tracing::warn!` log when it cleans an orphaned handle.

## TDD Instructions

1. **Write a test** that reveals a secret, sets its `last_accessed` to 70 seconds ago (using mock time or deterministic timer), then runs the Reaper; assert the entry is removed and a warning log is emitted.
2. **Write a test** where the secret is `InUse` (e.g., `perform_action` not finished) and `last_accessed` is old – Reaper must skip it.
3. **Write a test** that calls `release_secret` before the Reaper runs; assert the entry is already gone and Reaper does not log.
4. **Write a test** that reveals a secret, lets it become idle, then calls `perform_action` again – the Reaper must not have removed it if within 60s.
5. **Write a property‑based test** that randomly interleaves reveals, actions, releases, and Reaper runs, and verifies no secret is zeroized while `InUse`.

Implementation: use `tokio::time::interval` and `DashMap`’s iterator. Mock time with `tokio::time::pause()` in tests.

## Acceptance criteria

- [ ] Reaper runs every 10 seconds (configurable).
- [ ] TTL is 60 seconds of idleness.
- [ ] Logging includes the handle number (u64) for debugging.
