## What to build

React/React Native modal that:
- Listens to `VaultStateUpdate::ConflictDetected` event.
- Shows different text and options based on `is_toxic` flag:
  - **Valid conflict**: “This item was updated on another device. [Keep Server Version] [Force Overwrite with Local]”
  - **Toxic conflict**: “Your edit conflicts with an unreadable update (possibly from a key rotation). [Keep Local] [Overwrite Server]”
- Calls the sync engine’s `resolve_with_choice(uuid, choice)` method.
- Closes automatically after resolution, and triggers a sync refresh.

## TDD Instructions

1. **Write a Playwright test** that simulates a valid conflict (by forcing a 412 from the mock server) and asserts the modal appears with the correct message and two buttons.
2. **Write a test** that clicks “Keep Server Version” – asserts the local item is overwritten and the DashMap entry is removed.
3. **Write a test** for a toxic conflict – the modal text mentions “unreadable update” and the buttons are “Keep Local” and “Overwrite Server”.
4. **Write a test** that if the user dismisses the modal (closes it without choosing), the conflict is not resolved and the item remains in the DashMap (ignored).
5. **Write a test** that multiple concurrent conflicts are queued (modal shows one after another, not overlapping).

Implementation: use a global modal stack. The choice is sent via a method on the `VautrClient` stub that the UI holds.

## Acceptance criteria

- [ ] The modal is accessible (keyboard, screen reader).
- [ ] The user’s choice is immediately applied and the UI updates.
- [ ] The modal does not appear for items that are already resolved by the user.
