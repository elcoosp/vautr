## What to build

In `vautr-crypto` (or `vautr-sharing`):
- `generate_sharing_keypair() -> (SharingPublicKey, Zeroizing<SharingPrivateKey>)` using X25519.
- `wrap_sik(recipient_public_key: &SharingPublicKey, sik: &SymmetricItemKey) -> Result<WrappedSIK, CryptoError>`: generates ephemeral X25519 keypair, computes shared secret via DH, derives `KEK_SHARE = HKDF(shared_secret, "vautr-share-wrap")`, encrypts SIK with AEAD, returns `(ephemeral_public_key, ciphertext, nonce)`.
- `unwrap_sik(private_key: &SharingPrivateKey, wrapped: &WrappedSIK) -> Result<SymmetricItemKey, CryptoError>`: computes shared secret using ephemeral key, derives same KEK, decrypts.

## TDD Instructions

1. **Write a test** that generates a keypair for Alice and Bob, wraps a random SIK with Bob’s public key, then unwraps with Bob’s private key – must succeed and match original.
2. **Write a test** where wrapping uses a wrong public key (Charlie’s); unwrapping with Bob’s key must fail (TagMismatch).
3. **Write a test** that demonstrates forward secrecy: after unwrapping, the ephemeral private key is discarded; compromise of Bob’s long‑term private key does not allow decryption of old wrapped SIKs (if they were stored).
4. **Write a property‑based test** that rounds trips many random SIKs and keypairs.
5. **Write a test** that wraps the same SIK for two different recipients; assert the wrapped outputs are different (different ephemeral keys).

Implementation: use `x25519_dalek` for DH, `hkdf` for KEK derivation, and AEAD from VTR-012.

## Acceptance criteria

- [ ] The wrapped SIK includes the ephemeral public key in the envelope format (`sharing-envelope.md`).
- [ ] Unwrapping returns `Zeroizing<[u8; 32]>` for the SIK.
- [ ] No plaintext SIK ever leaves the `vautr-crypto` crate.
