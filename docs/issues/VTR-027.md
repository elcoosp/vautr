## What to build

In a new `vautr-import` crate:
- `import_from_csv(path: &Path) -> Result<ImportReport, ImportError>` that streams CSV, maps rows to `DomainModel`, generates new UUIDs, and checks duplicates against an existing in‑memory `HashSet<(title, primary_url)>` built from current vault.
- `import_from_bitwarden_json(...)` and `import_from_1pux(...)` (ZIP extraction).
- Uses size‑aware chunking (100 items or 25 MB plaintext) and parallel encryption with `rayon`.

## TDD Instructions

1. **Write a test** with a CSV of 1000 rows; assert import completes in <5 seconds and all items are inserted into SQLite with new UUIDs.
2. **Write a test** where 10 items already exist in the vault (title + URL match); assert they are skipped (duplicate) and the report shows `skipped_count = 10`.
3. **Write a test** with a malformed CSV line; assert the import continues (graceful degradation) and the report includes the line number and error.
4. **Write a test** that imports a 1Password `.1pux` (ZIP) and verifies all fields are correctly mapped.
5. **Write a memory test** that imports a 100 MB CSV file (simulated) and asserts peak RSS does not exceed 50 MB (streaming).

Implementation: use `csv::Reader` and `serde_json::StreamDeserializer`. For ZIP, use `zip::read::ZipArchive` with streaming extraction.

## Acceptance criteria

- [ ] The import runs in a background worker and does not block UI.
- [ ] A single `VaultStateUpdate::ImportCompleted` event is sent at the end.
- [ ] The FTS5 index is rebuilt after the import (not incrementally).
