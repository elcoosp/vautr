## What to build

- **Server**: on SIGTERM or SIGINT, stop accepting new requests, finish in‑flight requests (with timeout 30s), flush SQLite WAL, close connection pool, then exit.
- **Desktop client**: on window close or system shutdown, persist the DashMap to SQLite, flush any pending sync tasks, release all secret handles, then exit.

## TDD Instructions

1. **Write a test** that starts the server, sends a long‑running request (e.g., sync pull with delay), then sends SIGTERM. Assert the server finishes the request (returns 200) and then exits within 30s.
2. **Write a test** that the server rejects new requests after shutdown begins (returns 503).
3. **Write a test** for the desktop client that simulates a system shutdown (e.g., `ctrl_c` signal) and verifies that the `local_blacklist` table is updated with the current DashMap state (via a persisted flag).
4. **Write a test** that if the client is killed ungracefully (SIGKILL), the next startup recovers the DashMap from the last persisted snapshot (no corruption).
5. **Write a test** that the client’s shutdown timeout is configurable and respects pending file uploads (waits for them to finish or cancels).

Implementation: server uses `tokio::signal::unix` and `axum::Server::with_graceful_shutdown`. Client uses `ctrlc` crate and platform‑specific events.

## Acceptance criteria

- [ ] Graceful shutdown never loses pending mutations (server or client).
- [ ] The server can be upgraded with zero downtime (using a load balancer and rolling restarts).
