## What to build

Client function `export_vault(format: ExportFormat, path: &Path) -> Result<ExportReport, CoreError>` that:
- Iterates over all items, decrypts each (using `reveal_secret` and immediate `release_secret` per item).
- Writes to a CSV or JSON file (plaintext) in a streaming fashion (no loading all into memory).
- Includes all overview fields and secrets (password, notes, TOTP).
- The export is blocked if the vault is in Read‑Only gate (requires re‑authentication).

## TDD Instructions

1. **Write a test** that creates 100 items, exports to CSV, then imports that CSV into a new vault (using VTR-027) – asserts all fields match exactly.
2. **Write a test** that exports to JSON and validates the JSON schema (fields: uuid, title, username, password, urls, notes, totp).
3. **Write a test** that the export uses streaming and does not OOM on 10k items (peak memory < 10 MB).
4. **Write a test** that if the vault is locked or in Read‑Only gate, export fails with `CoreError::EpochMismatch`.
5. **Write a test** that the export respects user cancellation (progress events and cancel flag).

Implementation: use `csv` and `serde_json` writers. Stream decryption by iterating over the `item_overviews` table and decrypting one by one.

## Acceptance criteria

- [ ] Export is fully offline (no network calls).
- [ ] The user can choose which fields to include (optional).
- [ ] The export file is human‑readable and can be opened with any standard tool.
