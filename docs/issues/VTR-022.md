## What to build

A background `Reaper` task (in `vautr-sync`) that:
- Scans `quarantine` table for entries where `quarantine_until < now()`.
- For each expired item, pulls current metadata from server via `GET /sync/pull` (or dedicated fetch).
- If item is still toxic (same `enc_key_gen=0`), sends `DELETE /items/{uuid}` with `If-Match: target_version`.
- If DELETE returns 412 (server version changed), updates quarantine entry with new `target_version` and resets TTL (+90 days).
- If item is now valid, simply drops quarantine entry (no tombstone).

## TDD Instructions

1. **Write a test** that inserts an expired quarantine entry for a still‑toxic item, runs the Reaper, and asserts `DELETE` is called exactly once.
2. **Write a test** where the item became valid (server metadata shows `enc_key_gen` >= 1); assert quarantine entry is removed without deletion.
3. **Write a test** where `DELETE` returns 412; assert the quarantine entry’s `target_version` is updated to the new server version and TTL is reset.
4. **Write a test** that ensures the Reaper respects `retries` count and doesn’t loop indefinitely.
5. **Write a test** with no expired entries – Reaper does nothing.

Implementation: use `sqlx` for quarantine table, `reqwest` for server calls, and `tokio::time::sleep` for periodic scan (every 24h).

## Acceptance criteria

- [ ] Reaper runs every 24 hours (configurable).
- [ ] 412 resets TTL to 90 days from now.
- [ ] I/O is bounded – at most one attempt per item per 90 days.
