# Vautr native module (`@vautr/native`)

Expo TurboModule that links the Rust `vautr-ffi` core into the React Native JSI
instance, giving the mobile app a **local, zero-knowledge vault** whose secret
reveal goes through an opaque handle + native overlay (VTR-048 / VTR-061). Plaintext
never crosses into JS.

## Layout

```
modules/vautr-native/
├── package.json              # @vautr/native (Expo module)
├── expo-module.config.json   # registers VautrNativeModule on ios+android
├── VautrNative.podspec       # iOS pod (links libvautr_ffi.a)
├── src/index.ts              # createVautrNativeBridge() / createSecureEnclaveBridge()
├── android/
│   ├── build.gradle
│   ├── src/main/AndroidManifest.xml
│   └── src/main/java/expo/modules/vautr/
│       ├── VautrNativeModule.kt   # TurboModule wrapping uniffi MobileClient
│       └── VautrNativePackage.kt   # Expo package registrar
├── ios/
│   └── VautrNativeModule.swift     # Expo Swift module wrapping uniffi MobileClient
└── ffi-bindings/            # GENERATED by `cargo run -p vautr-ffi --example gen_bindings`
    ├── vautr_ffi.kt          # uniffi Kotlin bindings
    ├── vautr_ffi.swift       # uniffi Swift bindings
    ├── vautr_ffiFFI.h        # C header
    └── vautr_ffiFFI.modulemap
```

The `ffi-bindings/` directory is **generated**, not hand-written. Regenerate
after any change to `core/vautr-ffi/src/client.rs`:

```bash
cargo build -p vautr-ffi
cargo run -p vautr-ffi --example gen_bindings modules/vautr-native/ffi-bindings
```

## Building the Rust core

The Kotlin/Swift wrappers call into `libvautr_ffi` (cdylib for Android, staticlib
for iOS). Build per-target:

```bash
# Android (needs cargo-ndk + the Android NDK):
cargo install cargo-ndk
cargo ndk -t armeabi-v7a -t arm64-v8a -t x86_64 \
  -o modules/vautr-native/android/src/main/jniLibs \
  build -p vautr-ffi --release

# iOS (needs the relevant Rust targets):
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
cargo build -p vautr-ffi --release --target aarch64-apple-ios
# lipo the slices into modules/vautr-native/ios/libs/libvautr_ffi.a
```

`read_secret` is excluded from this artifact: it is gated behind the
`desktop-api` feature and `scripts/check-restricted-api.sh` asserts the symbol is
absent from the mobile build.

## Wiring

- `apps/mobile/lib/client.ts` → `bootVautrCore()` resolves the bridge via
  `createVautrNativeBridge()` (from `@vautr/native`), then calls
  `initializeVautrCore({ native, secureEnclave, dbPath })`. When the native
  module is absent (dev build without the Rust toolchain), it no-ops and the app
  falls back to the HTTP client.
- `apps/mobile/package.json` depends on `@vautr/native` (`workspace:*`); the
  module is registered in `pnpm-workspace.yaml` under `modules/*`.

## Verification status

- `core/vautr-ffi` builds and its 3 in-crate integration tests
  (`mobile_unlock_list_reveal_release_lock`, `mobile_locked_rejects_reads`,
  `overlay_renders_plaintext_only_in_native_handler`) pass — they exercise the
  full uniffi flow including the opaque-handle overlay (Rust side is verified).
- The Kotlin/Swift bindings are generated from the compiled dylib
  (`ffi-bindings/`) and the wrappers are written against that exact API.
- **Not run in CI/sandbox:** the actual `cargo ndk` / `cargo build --target
  aarch64-apple-ios` + `pod install` / Gradle assemble, because the Android NDK,
  Xcode, and `expo-modules-core` native toolchain are unavailable here. The
  native compile is the one environment-gated step; everything else is real.
